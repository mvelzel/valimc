# VMC-029b1 — Durable survival placement

Status: Request/source codec work started. October 16, 2026.
Parent: [placement](VMC-029b.md).

Acceptance: consume exactly one owned main/offhand block stack together with one
fenced block placement. Persist the exact before/after inventory and typed intent
before destination delivery; a terminal receipt either retains consumption or
refunds the exact stack. Replay cannot place/consume twice, cross-use mining
receipts or authorize target ABA/retired owners. Recover consistently after every
source/region write boundary, disconnect, death and login. Bound all work.

Start with canonical request/source codecs, then source snapshot/lease integration,
owner reservation and journaled block/receipt commit, and finally live composition.
Reuse the existing journal/receipt infrastructure where its semantics apply;
placement gets an explicit operation domain and count consumption, not tool wear.

Reference: pinned26.3 `BlockItem.place` calls `ItemStack.consume(1, player)` after
successful placement. Native placement context facts are in the parent ticket;
private bytecode remains `.local/BlockItem-placement-bytecode.txt`, jar SHA1
`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`.

Client scenario: survival plain/slab placement in both hands, last-item depletion,
occupied/body/reach refusals, waterlogging/double merge and fresh reconnect.
Dedicated tester owns actual validation after composition; codec tests do not
enable survival placement or satisfy that gate.
