# VMC-043e19 — Opening shulker lids displace entities

Status: Awaiting client
Milestone: M3
Depends on: [VMC-043e18](VMC-043e18.md).

An opening shulker pushes entities met by the swept face of its lid. Apply
that external move while the mob ticks, before later mobs think and travel,
and through the existing group effect path for neighboring sections and players.

Acceptance:

- All six faces and partial opening match the pinned native lid sweep and
  displacement; closing and an unchanged peek do not push.
- Shulkers, spectators and entities without physics are excluded. NoAI alone
  does not make an entity immune to an external move.
- Moves use ordinary collision and step-up, without the piston movement cap
  or its exemption for blocks moving in the same direction.
- Local mobs see the displacement immediately. Other section stores and hosted
  players receive it through the existing owner path, without a second own tick.
- Actual-client testing remains deferred at the user's request.

Reference: Mojang 26.3 server SHA-1
`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`, `Shulker.onPeekAmountChange`,
`getPhysicalPeek`, `getProgressDeltaAabb` and `Entity.move(MoverType.SHULKER)`.
The sweep is only the slab added beyond the previous physical peek. The move
length is the float32 difference between physical peeks, along the opposite
of the attachment face. Closing does not push.

Deferred client scenario: stand on an opening floor shulker and next to a wall
shulker, with a dropped item and a mob in the lid's path. Observe displacement,
block collision and the absence of a pull while the lid closes.

Implementation: the family emits only the swept lid slab and its float32
move. The live mob ticker applies local moves before the next mob thinks,
updates the spatial grid and amends steps of mobs that already ticked. The
owner forwards the effect to other section stores and hosted players using
the existing sibling/player effect path. External moves preserve the entity's
own simulation and ageing stamps. NoAI shulkers still animate their lid.

The kernel shares the existing piston collision/response code while keeping
the lid mover free of piston limits and exemptions. Both new NIFs run on a
dirty scheduler. The new external mover distinguishes local movement authority
(ground-state updates) from simulation eligibility (collision response): native
players are client-authoritative but also simulate on the server. The existing
piston caller's corresponding repair is in [VMC-048b1](VMC-048b1.md).

Validation: `ShulkerPushOracle` invokes the actual native lid callback in 5,376
cases, including all six faces, partial and full changes, closing, unchanged
peeks, blocks, four mob variants including NoAI, items, XP, players/spectators,
arrows, TNT, falling blocks, crystals and no-physics exclusions. Exact positions,
velocities and ground flags match; the interleaved mob NIF also matches with the
live lid collider installed. The source keeps its anchor.

All 57 focused owner, group, collision, lifecycle and socket tests pass. The
hosted socket player rises with a floor lid, stays when it closes and is excluded
as a spectator. Local targets before/after the source in tick order and targets
in either neighboring section move once and retain one lived/age tick. Oversized
moves and complete collider sets above 256 are refused. That boundary test exposed
an extended collider whose centre was in the next grid cell; queries now search
the centre halo before filtering physical boxes.

Seven affected native stages pass (87 seconds, six cache hits); the final four
movement/lid/piston stages pass again after the boundary correction. Core Rust's
124 tests, NIF compilation, Clippy and the production build without parity entry
points pass. Clippy retains only existing type-complexity warnings. Evidence:
`.local/m3-shulker-push-{native,check,tests,final-tests,rust,final-rust,stages,final-stages,audit}.log`.
