# VMC-018c1 — Player interaction ranges

Status: Done
Note: Done — default interaction ranges validated. Updated: October 14, 2026. Depends on saved game-mode initialization (VMC-016b1).

## Scope and acceptance

The preview sends no player range attributes and checks a fixed six-block sphere
around each block center. Initialize the two native interaction attributes and
use the native eye-to-block-box distance with its one-block server verification
buffer. Placement checks the clicked block rather than the adjacent destination.
Reject inconsistent hit locations before a world mutation.

- Extract pinned builtin attribute IDs/defaults/ranges and the native creative
  transient modifiers. Send the block/entity range attributes at login, derived
  from saved mode. Client packets and saved ability flags cannot grant range.
- Compare exact native attribute packet bodies for every mode; Mojang must decode
  the Elixir output with the same holder/base/modifier identity and value.
- Compare box-distance boundaries, strict range equality and hit-location bounds
  against pinned native arithmetic. Test negative coordinates and rejected remote
  targets without loading their regions. Preserve acknowledgments and the existing
  preview mode/inventory gates.
- Keep range calculations pure and connection-local. No process per attribute,
  global gameplay coordinator or mutable shared attribute map is needed.
- Run format/full tests/native oracle/release/diff review/public-tree audit.

Actual Minecraft 26.3 / CUA: join creative, observe `/stats`, place/break at a
distance within the five-block creative range above the prior unsynchronized default,
then move beyond client reach and confirm no placement. Reconnect/full restart
retain the initialized range. Join a non-creative saved mode and confirm its
shorter client targeting range and unchanged preview world restrictions. Keep
raw captures/worlds/oracle output private.
