# VMC-043e26 — Dolphin treasure guidance outside the owner

Status: Awaiting client
Milestone: M3
Depends on: [VMC-043e5](VMC-043e5.md), [VMC-043e25](VMC-043e25.md).

A fed adult dolphin finds nearby treasure and guides the player toward it.
The structure search must run outside the simulation owner through its existing
bounded job table and generation pool. The goal waits for its own request's
answer, chooses native water waypoints and retains its fish state when low air
interrupts the journey.

Acceptance: actual native treasure-goal traces match lookup origin/tag/radius,
waypoints, controls, movement, events and random draws for near, far and absent
treasure. Live queries do not block an owner, stale answers cannot satisfy a
new request, and busy work adds no unbounded queue. Actual-client tests remain
deferred.

Reference: Mojang 26.3 server SHA-1
`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`,
`Dolphin.DolphinSwimToTreasureGoal`, `closeToNextPos`, `DefaultRandomPos`,
`ServerLevel.findNearestMapStructure` and `StructureTags.DOLPHIN_LOCATED`.
The query uses radius 50 and does not skip referenced structures. A low-air
stop preserves `GotFish`; arrival or a stuck search clears it.

Implementation: the goal emits a bounded query effect with a fresh request
reference. The existing owner job table, bounded task supervisor and generation
pool run at most one structure search per section. Busy goals re-emit their
request without adding a queue. One completed result waits for the matching
goal to consume it, including across unticked selector turns and NoAI. The
existing job token/epoch routing handles stale workers; the goal reference
rejects a result for an earlier attempt. Arrival chooses native waypoints and
plays event 38; air interruptions preserve the fish for a later attempt.

The full native journey exposed stale fluid observations at surfacing and a
generic re-entry splash. Mobs now refresh fluid/eye observations before AI each
turn, and dolphins read the resulting water state after movement. Their existing
remembered water flag is removed. A family splash-sound hook selects the native
dolphin sound through the existing generated sound IDs.

Validation: six native routes (720 complete mob ticks) match lookup origins,
tag/radius, treasure, waypoints, goals, controls, travel, random draws and events
for near, far and absent treasure, with full or low starting air. The supplied
oracle structure answer replaces only the expensive lookup. All other native
goal and movement code runs normally. Before the water repair, the first route
diverged at tick 82 on surfacing; at tick 88 the sound comparison exposed the
generic splash. Both now match.

All 27 focused checks pass across the final combined run and corrected owner
fixture rerun. They cover request matching, low-air retention, arrival, missing
structures, live job delivery, NoAI result retention, paths and headless socket
sessions. All ten affected native areas pass: `dolphin_treasure`, `mob_ai`,
`water_age`, `puffer_touch`, `shulker_push`, `tcp`, `hostile_ai`, `nether_mobs`,
`animals`, `village`. One shared dev-build check hit a native-library load race;
subsequent checks use isolated build assets. Evidence:
`.local/m3-dolphin-treasure-{native,stage,tests,final-tests,owner-tests,stages,shared-stages,library-load-failure,audit}.log`.

Deferred client scenario: feed a generated dolphin a cod in an ocean, follow
its treasure route, allow a breathing interruption and observe continued guidance.
