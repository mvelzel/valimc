# VMC-045a7 — Reachable and durable first dragon fight

Status: Awaiting client
Milestone: M3
Depends on: [VMC-045a5](VMC-045a5.md), [VMC-045a6](VMC-045a6.md).

Entering the central End arena loads its chunks and admits one live dragon.
The origin section owns the fight record in the group's shared log. Dragon
completion changes the portal, first egg and next gateway in the same group
frame as the entity removal. [VMC-045a8](VMC-045a8.md) adds live four-crystal
respawn.

Acceptance:

- Nearby living players, including creative/spectator, keep the central
  arena loaded. No dragon spawns before the necessary chunks and owners are
  ready; admission does not block simulation on generation or storage.
- One dragon UUID survives section moves and restart; its audience sees the
  pink boss bar and current health. Healing/path selection use the arena's
  actual crystal count, and the first fight awards its native XP total.
- Only that dragon's completion activates the exit, places the first egg
  and creates one gateway. Repeated completion cannot duplicate rewards.
- Owner and socket checks cover admission, health, cross-section completion
  and crash/reload. The parent finale batch kills the dragon and exits on
  the actual client before this slice can be Done.

## Implementation and evidence (October 24, 2026)

The End origin section retains one fight record in its normal shared-log
parts. The group publishes it to its sibling actors alongside their stores,
so the tracked dragon reads the actual spike-crystal count and first/repeat
kill flag. Crystal destruction recounts before the selected dragon's damage
and retaliation. A missing dragon is found or created without duplicating a
loaded UUID. Admission waits for all 289 central chunks in the same writable
group, while generation stays in its existing scheduler.

Each nearby alive player's existing loading/simulation tickets cover the
arena. The audience includes spectators and creative players and refreshes
every twenty ticks. Its pink bar uses the generated native codec and sends
fresh health. The connection's projected view includes whether the player
is alive, and tickets refresh when that or the vertical audience membership
changes inside the same chunk. The connection retains this ticket state
when handing its gameplay session to a group.

The actor's final removal hands completion directly to the origin through
the existing sibling effects. UUID fencing, the active podium, the first
egg and one seed-ordered gateway become changes of the same group frame.
Gateway block-entity metadata precedes its block edits. The shared edit
action has an explicit drop bit, preserving the native podium's conditional
destruction, spills and neighbour updates; feature writes respect the End's
build height. A full entity store defers dragon creation.

Three final owner/socket scenarios pass: delayed admission and UUID reload;
the full 200-tick death from a sibling with 12,000 first-kill XP, one portal,
egg, gateway and a replaced wool block's drop, followed by reload; and an
actual spectator connection receiving native add/health/remove bar packets
while its arena tickets withdraw on a vertical departure. Fixtures import
flat End columns and the owner scenario supplies its audience row; the
socket scenario uses the real hosted player and a shared head-hit call.
Focused entity, crystal, projectile, storage, group/handoff, view-distance,
player-save and portal suites pass. Both changed Rust crates pass their
checks (124 core tests), with only existing Clippy type-complexity warnings.
All 100 affected vanilla stages passed; the final connection-view repair
also passed the plain/encrypted native socket stage separately. Publication,
documentation and layering audits pass.
