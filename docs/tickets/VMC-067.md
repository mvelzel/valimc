# VMC-067 — One entity model for items and XP orbs

Status: Awaiting client
Milestone: M1 foundations
Depends on: [VMC-064](VMC-064.md), [VMC-066](VMC-066.md).

Items and experience orbs each grew their own entity plumbing: separate view
construction, separate ETS publications (items as one region-wide map, orbs per
chunk), separate readers, two replication trackers per connection, separate
pickup animation paths and two id allocators. Every connection copied a region's
whole item map out of ETS every 50 ms whether anything changed. Orb bodies
(motion, ageing, despawn) exist as a model but were never wired, so orbs never
age or despawn in play.

Scope: one entity view, one publication, one reader and one replication path for
both kinds, and a shared lifetime so orbs age and despawn like vanilla (6,000
ticks). Orb physics (falling, flying to players) stays with VMC-034n4c, which
this unblocks. Kind-specific durability stays: items in the item ledger, orbs in
container records (deterministic UUIDs, immutable births).

Acceptance:

- Per-chunk entity rows for both kinds with an `{epoch, revision}` stamp; only
  changed chunks are rewritten; observers copy a chunk's views only when its stamp
  changed.
- One `EntityReplication` tracker per connection; orbs keep client-predicted
  motion corrections; pickup animations resolve through the same tracker.
- One view builder and one entity id allocator (bounded at 2^31 − 1) for both kinds.
- Orbs age with the region tick and despawn at 6,000 ticks, durably.
- Client check: item and orb spawn, pickup and despawn; many dropped items near
  several players stay correct.

Progress:

- Step 1 (October 20, 2026): `Valimc.World.EntityPublication` writes
  `{{:entities, chunk}, {epoch, revision}, views}` rows for items and orbs from
  their last durable views (kept as `{:entity_source, kind}` rows) and a chunk
  hash index; only changed chunks get a new revision, emptied chunks are deleted.
  `World.visible_entities/3` reads each visible chunk's stamp with
  `:ets.lookup_element/3` and copies its views only when the stamp changed (a
  per-connection cache). Connections keep one `EntityReplication` tracker; orb
  views carry `kind: :orb` and keep predicted motion corrections. The region-wide
  `{:items, views}` row and the orb row bookkeeping are gone.
- Step 2 (October 20, 2026): `Valimc.World.EntityView` builds the shared view
  (identity, chunk, spawn/metadata/position/motion packets, byte accounting) and
  allocates entity ids bounded at 2^31 − 1 for both kinds; items add their stack
  revisions and merge hints, orbs their value and count. Item and orb suites (819
  tests) pass unchanged, so packets are byte-identical.
- Step 3 (October 20, 2026): orbs age with the region tick. The new pipeline
  phase `RegionData.orb_lifetime/1` accumulates ticks in memory and, when an orb
  would reach 6,000 or every 30 s, calls `CookingOrbBodies.advance/3`, which rests
  awards without bodies at their births (age 0) and then ages every live row,
  retiring the remaining units at 6,000; the containers write is group-committed
  and the orb runtime republishes on the new body revision, so a despawned orb's
  view (and its client entity) disappears. It runs only when no planning worker
  holds a container snapshot. Up to 30 s of age progress is lost on a crash.
  Orb motion (launch, falling, attraction) remains VMC-034n4c.
  Checks: orb suites 62, fast suite 1,023. Next: milestone client run (item and
  orb spawn, pickup, despawn; many items near several players).
- Despawn fix (October 20, 2026, found by the M1 client run): item ageing waited
  whenever an item planning worker held the owner (a worker's result replaces the
  item map), so a player standing near items, whose pickup queries keep the slot
  busy, stalled their despawn clock indefinitely. Skipped ticks are now owed
  (`item_age_debt`) and applied at once (`ItemMotionState.advance/2`), so items
  despawn at 6,000 ticks regardless of contention. `test/item_despawn_test.exs`
  holds the planning slot for 6,000 ticks and then sees the item removed.
