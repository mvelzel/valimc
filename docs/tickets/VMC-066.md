# VMC-066 — Tick pipeline on game time

Status: Planned
Milestone: M1 foundations
Depends on: [VMC-063](VMC-063.md). Behaviours that use the ticks come with VMC-068
and later milestones.

Region owners tick every 50 ms, but each subsystem (items, cooking, orbs) keeps
its own wall-clock cadence, there is no game-tick counter shared by the phases,
no scheduled or random block ticks, and tests wait on real time (`Process.sleep`,
millisecond deadlines), which made suites flaky under concurrent load.

Scope: the region tick becomes one ordered pipeline driven by a per-region game
tick; scheduled and random block ticks exist as owner primitives; tests can step
the clock deterministically. No new block behaviour beyond what proves the
primitives.

Acceptance:

- One pipeline per region tick in fixed phases: scheduled block ticks due at this
  game tick, random ticks, items, cooking, orbs, then publication. Every phase
  receives the game tick; a late owner catches up at most a bounded number of
  ticks per wake (vanilla skips rather than bursting without bound).
- Scheduled ticks: per-region queue ordered by (due tick, priority, insertion),
  deduplicated per (position, block), bounded per region, persisted with the
  region (survive restart), executed only if the block at the position still
  matches.
- Random ticks: `randomTickSpeed` (3) positions per section per tick, only in
  sections that contain randomly ticking states (a generated fact), driven by a
  seeded per-region RNG.
- Steppable clock: `Region.step(owner, ticks)` runs the pipeline synchronously
  with a frozen time source; with `:region_ticks: :manual` (tests) no timer
  fires. At least the item/cooking tick suites move from sleeping to stepping.
- No phase blocks on storage (VMC-063); backpressure defers commits.

Reference: vanilla `ServerLevel.tick` phase order, `LevelTicks` scheduling
(`ScheduledTick` ordering by trigger tick, priority, sub-tick order),
`ServerLevel.tickChunk` random ticks (`randomTickSpeed` game rule, default 3).

Checks: targeted region tick tests; fast suite at the end of each step.
Next: write the step plan with the pipeline module first.
