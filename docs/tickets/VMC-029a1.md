# VMC-029a1 — Atomic mining persistence

Status: In progress. October 16, 2026. Parent: [survival mining](VMC-029a.md).

Acceptance: block removal and its item records/transfer receipts commit together.
A crash at any file-write boundary recovers one consistent outcome; retry cannot
pay drops twice. Fence region incarnation, revision, source receipt and writer
lease. Keep disk work in the existing region writer, with one bounded pending
proposal and no world-wide transaction process.

Plan: a checksummed write-ahead record contains bounded owner-local block edits
and the proposed existing item ledger. Persist it before replacing either normal
file; remove it only after both files are persisted. A new writer finishes any
valid pending record before serving loads or writes. Failed writes retain the
record and retire the owner. Ordinary writes cannot overtake a pending proposal.
This keeps current block/item formats and avoids a world migration. Recovery
reapplies block edits idempotently; the receipt identifies the same item outcome.

First slice: bounded transaction codec, including corrupt/truncated/checksummed
invalid records, wrong region, duplicate edits and item-ledger validation. Then
writer recovery and owner publication, followed by player tool-consumption
coordination. The codec alone does not enable a mining transaction.

Codec implemented: at most4,096 unique edits plus the bounded existing item ledger,
version/data/region header and SHA256. No term deserialization or decompression.
Boundary regressions cover the full edit limit, damaged outer/inner checksums,
duplicate or cross-owner edits, invalid states and retained item receipts. Raw
checks `.local/mining-record-tests.log` pass two codec regressions and six mining
regressions.

Writer implemented: a valid leased proposal persists its journal, block snapshot
and item ledger before acknowledgement; I/O failure retains the intent and stops
the writer. Acquisition completes recovery before granting a lease. Five writer
regressions cover success/reopen, all three persisted restart boundaries, an
actual failed item-file replacement with a queued stale snapshot, corrupt intent,
stale leases and mismatched block outcomes. Recovery canonicalizes generated-air
edits and removes completed intent so later snapshots remain later. All75 affected
storage/death/outbox/login/cold-load checks pass, including the existing writer
lease tests. Logs `.local/mining-store-{tests,affected-tests}.log`.

Region backend implemented: at most128 owner-local permits, each covering at
most128 blocks for10seconds. Target mutation invalidates a permit even when the
same state returns; unrelated edits continue. Owner restart loses old permits.
The existing bounded item worker pool prepares item plans and shared block
frames; the owner rechecks the permit before writing. Blocks/items publish only
after the journaled write. Pending writes fence mutations/flush/save; shutdown
cannot flush the old dirty snapshot over the new outcome.

Domain-separated receipt digests distinguish applied/rejected outcomes without
changing the existing item-ledger format. Replays return the prior result even
after restart or permit expiry. Rejected/expired permits mint nothing; the future
player coordinator must refund any prepared wear. No global revision gate means
an unrelated miner does not invalidate another player's request.

Nine backend/permit regressions pass, alongside the preceding99 affected checks: hidden pending
publication, callback domains, concurrent miners, target ABA, no-drop mining,
restart/replay, graceful shutdown and an actual failed writer/recovery. Logs
`.local/mining-region-{tests-final,affected-tests}.log`. An earlier combined run passed
87/88 with an on-exit `File.rm_rf!` cleanup error; the expanded99-test run passed.
The frozen backend `27f85df69835ca16d1d63a4b737b3c5cd3a51c3f` (619 verified
blobs, no mismatches) passes790 full tests, seed327342, and a separate production
release. Full native integration is running. Logs
`.local/mining-backend-{full-tests,production,full-native}.log`; manifest
`.local/mining-backend-validation-checkpoint.json`. The live GUI release remains
unchanged. The earlier cleanup error did not recur in the full suite.

Next: player intent codec, tool-wear/refund and source-journal recovery, native
loot planning and live start/abort/stop. Internal inbox calls require a durable,
fenced source; this backend does not yet authorize or enable live player mining.

Client scenario after live integration: mine basic supported blocks, inspect
drops/tool wear, reconnect and repeat after induced writer/owner restarts. The
dedicated client tester owns these checks; native mining probes cannot replace them.
