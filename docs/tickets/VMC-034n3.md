## Materialization kernel

`CookingOrbs.materialize/3` proposes a whole `Containers` successor for one pending
award. It preserves the immutable award/recipe obligation, receipt, slots and entry
revisions. The owning region must validate its lease/current state and durably
commit before publishing effects. The local runtime now calls it on a bounded
worker; live earned-output creation composes through VMC-034n5.

Split each recipe's decided XP separately using eleven denomination divisions,
then aggregate equal values into explicit counts. Persistent version-8 UUIDs derive
from award identity/value; runtime entity IDs are absent from storage. A marker and
its complete orb map share version-5 container bytes, with at most 256 markers,
2,816 records and 137,986 ledger bytes. Zero XP has an empty marked map and retains
recipe delivery. Encode/decode reject partial/altered/orphan records; the frozen
pre-pickup format cannot silently consume XP. No process/loop per XP unit.

The local kernel returns `xp_orb_handoff_required` for boundary-crossing positions;
the live runtime routes these through the [remote protocol](VMC-034n3a.md) and
[delivery inbox](VMC-034n3b.md). Destination adoption owns the sole creation effect.
Snapshot versions 1–4 retain exact bytes when the local ledger is empty; version 5
adds local creation records, version 6 adds transfer decisions. Existing joint
mining/container recovery embeds these without another journal or side file.

Native `ExperienceOrb.getExperienceValue/getIcon`, `DATA_VALUE` and generic entity
codecs are observed by original `ExperienceOrbOracle`. Metadata uses accessor 8,
integer serializer 1; Java 26.3 spawns XP through generic `add_entity`. Bounded spawn,
value metadata and removal now serve staged XP presentation; motion/position
remain static. Reference inspection stays in `.local/experience-orb.javap`.
