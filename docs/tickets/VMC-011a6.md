# VMC-011a6 — Fence independently supervised resource writers

Status: Done — supervised writer/lease slice. October 15, 2026. Parent: VMC-011a.

A resource's file writer was linked directly to its simulation owner.
Separate writer supervision before moving resources between domains; copying
state or changing links cannot transfer an OTP child's parent/lifecycle contract.
Use a bounded writer supervisor/registry and one monitored owner with a fresh
lease token. The owner monitors writer failure. Mutating writer requests require
that lease; readback is diagnostic observation, never simulation authority.

Acceptance for this integrated lifecycle slice:

- Every existing block/item write/flush uses the current lease. Reacquiring after
  owner death rotates it; late messages from an earlier owner cannot write.
- A live owner excludes another claimant. Abnormal owner death removes or fences
  its writer; replacement recovers actual files/journals, not proposed state.
- Existing writer failure/deadline/recovery behavior and unchanged file formats
  pass targeted persistence/outbox tests. Keep cold supervisor startup free of I/O.
- Actual client: edits, durable scene item lifecycle, reconnect and fresh logs on
  a frozen checkpoint, with the complete existing dataset preserved.

This is writer lifetime separation, not resource/domain handoff. No live transfer
API is admitted yet: a future transfer must first quiesce writes, fence the old
owner's cleanup, transfer writer lease and publish new routes as one protocol.
Do not add unlink/relink ownership shortcuts or resume two copies after failure.

Implemented: the same per-resource writer now belongs to a bounded dynamic
supervisor, monitors its owner and is monitored back. Claims exclude a live owner;
claiming after death rotates the lease and flushes the old monitor. Snapshots,
item commits, flush and close reject stale leases. Retry only an authoritatively
dead writer; never start a duplicate because an observation times out. Normal
resource cleanup closes its current lease; current no-handoff rules make its
timeout kill safe. Future transfer must first remove that cleanup authority.

Verification: 117 affected lifecycle/world/item/outbox/recovery tests pass. New
tests use actual owner death with a queued claim before DOWN, then stale block,
item, flush and close requests on the same surviving writer; real files stay
unchanged until a current-lease write. Native plaintext/encrypted TCP integration
passes (only that section of the existing driver, retained privately).
