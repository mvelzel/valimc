# VMC-029b2 — Ordinary full-cube placement

Status: Scoped; implementation/client gate pending. October 16, 2026.
Parent: [placement](VMC-029b.md); uses [durable consumption](VMC-029b1.md).

Acceptance: admit ordinary single-state full cubes through the existing bounded
creative/survival lanes. Preserve components, exact one-item consumption,
collision/replacement rules, durable receipts and reconnect. Do not admit gravity,
directional, block-entity or specialized callback blocks by matching their appearance.

Pinned26.3 registry inspection found182 blocks with exact `Block.class`, one state,
ordinary `BlockItem`, nonreplaceable default state and native full collision cube.
Together with the current glass exception, the potential plain catalog has183
items (178 additions). Pinned bytecode confirms `Block.getStateForPlacement`
returns the default state; `setPlacedBy`, `onPlace`, `neighborChanged` and indirect
neighbor updates are inert; `updateShape` retains its input state. Contextual
replacement and the effects on adjacent specialized blocks still need checking.
Private classifier/output: `.local/PlacementCandidates.java`,
`.local/placement-candidates.{json,log}`, `.local/Block-placement-scope-bytecode.txt`;
same pinned jar SHA1 as the parent.
This classification alone does not establish full gameplay/callback parity.

An isolated prototype of the183-item plain catalog matches1,319,700 actual native
contexts, all six faces and both horizontal cursor halves, plus the existing576
packets/nine nonfinite controls. It includes all101 slab families. Logs
`.local/ordinary-placement-all-faces-{native,check}.log`; prototype sources/facts
stay ignored. Production admission is unchanged pending the source catalog update.
Native consumption additionally matches2,840 cases across284 plain/slab items;
1,420 survival intents round-trip the exact outcomes in the isolated prototype.
Logs `.local/ordinary-consumption-{native,check}.log`.

Plan: extend the original native catalog/probes, sample every admitted block
against solid/air/liquid/slab contexts and all relevant faces, compare native count
consumption, then run affected source/owner/TCP checks. Keep runtime facts compact;
reuse immutable lookup tables and existing transfer ownership. Actual tester places
several newly admitted stone/wood/mineral-storage/color families in both modes, checks refusal,
stack depletion and fresh reconnect. Broader neighborhood updates remain in the
parent ticket; explicitly exclude any family requiring an unimplemented callback.
