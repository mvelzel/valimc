# VMC-034n1 — Cooking XP award values

Status: Implemented; client baseline pending. Foundation for [earned output](VMC-034n.md);
no live award admission.

Calculate each stored recipe's XP using the pinned native float32 product,
floor and conditional random round-up. Return a bounded immutable proposal with
the recipes to unlock and the random draws consumed. Neither mutate recipe credit
nor emit entities/player XP here. A durable caller must retain the exact proposal
across retries; recovery must never draw again for an already decided award.

Acceptance:

- Differential observations of native `AbstractFurnaceBlockEntity.createExperience`
  cover all stock XP rates, zero awards, integral/fractional products and strict RNG ties.
- Validate the existing bounded recipe-use map and supplied native 24-bit draws;
  bound iteration by the 107 pinned recipes. Unknown recipes, invalid counts,
  missing required draws and unsafe integer overflow refuse the whole proposal.
- Mixed recipes produce deterministic per-recipe decisions and totals; integral
  products consume no draw. Inputs and existing output-refusal behavior stay intact.
- A dedicated actual-client baseline verifies joining, live cooking and retained
  XP-output refusal on the frozen checkpoint. This unused kernel establishes no
  graphical orb, pickup, recipe-unlock or durable award claim.

Reference: Mojang 26.3 server SHA-1 `33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`,
`AbstractFurnaceBlockEntity.createExperience`, `Mth.floor/frac`, `RandomSource.nextFloat`.
Private bytecode/probe outputs stay under `.local/` and `research/`.

Checks: 33 affected tests pass (seed 526160): `cooking_awards`, `cooking_recipes`,
`cooking_connection` and `container_store`. Changed-file formatting passes.
`CookingExperienceOracle` and `check_cooking_experience.exs` match 712 actual native

The proposal contains all credited recipe identities/counts (even zero-XP outcomes),
per-recipe amounts, total XP and only the consumed 24-bit samples. Recipe-key order
is deterministic; it need not reproduce vanilla map iteration/RNG sequencing.
Supplied samples establish native rounding semantics, not Java RNG-state parity.
No source state is changed. Recovery must persist this decision before any effects.
