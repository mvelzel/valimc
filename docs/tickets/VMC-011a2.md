# VMC-011a2 — Client-tick position admission

Status: Done within transport-admission scope. October 15, 2026. Child of VMC-011a.

Native 26.3 permits one position-bearing movement packet between client tick-end
markers. This is a transport-order boundary, separate from the server simulation
clock. The preview currently ignores the marker and accepts repeated positions.

Acceptance:

- Connection-local admission rejects a second Pos/PosRot in the same client tick,
  including before load/teleport completion. Rotation/status do not consume it.
  Only a valid empty tick-end frame resets it; publication timers do not.
- Preserve per-socket order and reset on reconnect. Constant-size state, no new
  process, queue or timer. Do not claim authoritative movement or tick simulation.
- Invoke actual native movement/tick-end handlers for bounded ordered traces;
  test duplicate isolation, independent sessions, delimiter payload validation,
  teleport-pending admission and multiple framed packets in a single TCP write.
- Targeted checks only for this commit. Dedicated actual client: reconnect,
  sustained walking/sprinting/jumping, idle then movement, commands and fresh logs.
  Use an immutable checkpoint and preserve the complete test dataset.

Reference: Mojang 26.3 SHA-1 `33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`,
`ServerGamePacketListenerImpl.handleMovePlayer` / `handleClientTickEnd`, fields
`receivedPositionThisTick` and `receivedMovementThisTick`. Private bytecode:
`research/disassembly/VMC014c3-ServerGamePacketListenerImpl.txt`.
Pinned Paper `a2d844f` retains the same admission in its listener patch; its
tick-end hook adds an event rather than changing this flag boundary.

The server listener's tick resets movement-rate counters, not this position flag.
The tick-end handler also clears native known movement when none arrived; that
simulation state is a later slice. Existing load, teleport and movement-policy
differences remain explicit rather than being hidden in this protocol change.

Implementation: constant-size protocol state in each connection; position-bearing
packets consume it before preview movement, and exact empty delimiters release it.
Test peers/load driver now send delimiters for successive simulated client ticks.
No server timer releases the allowance. Five new regressions plus 24 affected
connection/replication/persistence tests pass. Actual native pre-load/won-game
handlers match 1,250 ordered traces; world simulation is deliberately bypassed
after the admission gate. Python compile/format/diff checks pass. Private logs:
`.local/vmc011a2-*`.

Updated-driver smoke: 32 clients for 2 seconds each, dense and spread, each sent
1,280 positions plus 1,280 delimiters with zero disconnects. Raw workloads/results
and driver/implementation hashes: `bench/results/vmc011a2-{dense,spread}-32.json`.
This verifies the load driver's new packet boundary, not relative server speed;
historical published measurements retain their older workload.

Dedicated Java 26.3 client passed on immutable `11c4280`: sustained walking,
sprinting and crouching, single jump/landing, idle recovery, reconnect/movement
and visible `/stats`. No false movement disconnect or fresh client/server issues;
source/receipt cleanup is consistent. CUA cannot combine Space+W, so jumping was
tested separately. Report: `.local/client-tests/VMC-011a2/report.md`.
