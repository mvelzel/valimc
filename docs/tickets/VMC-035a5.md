# VMC-035a5 — Durable item owner handoff

Status: Done
Note: Done within trusted owner-handoff scope. October 16,2026. Parent: VMC-035a.

Acceptance: moving an item across owners preserves UUID/stack/motion and cannot
lose or duplicate it after crashes, retries, concurrent opposite-direction moves
or source receipt replay. Source withdrawal persists before destination publication;
destination receipt persists before source intent clearance. Reconnect/recovery
converges to one item. Bound batches, records, bytes, workers, timers and retries.
Actual-client gate: cross a region boundary in both directions, reconnect, and
verify one visible item with conserved stack and committed source/destination state.

Design: keep one bounded outgoing intent per region (≤32 records, one destination),
a monotone source sequence and separate incoming region receipts. Player receipts
retain their current meaning and bytes. Persist a bounded ledger around the legacy
ItemRecords payload; emit legacy bytes while its extra state is empty. All ordinary,
critical and block/item journal saves must preserve this ledger. Source/destination
I/O stays in leased writers; one bounded worker drives each active delivery.
Independent owners can receive while sending, avoiding opposite-direction deadlock.
Active items retain their 256/.5MiB budget; one outgoing batch has a separate bounded
budget so simultaneous full-owner exchanges can make progress.

Keep birth-source retry receipts after departure/removal. Incoming receipts fence
replayed sequences. Carry a positive per-item ownership generation on handoff and
persist it with owned UUIDs: observer samples can span the two publications, so
replication must deduplicate UUIDs in favor of the newer generation before pacing.
Do not activate automatic motion until this ownership/recovery path is composed.
