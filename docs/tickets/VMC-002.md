# VMC-002 — Advertise executable custom commands to the client

Status: Done. Updated: October 13, 2026.
Depends on completed VMC-001.

## Scope and acceptance

The preview executes `/help`, `/stats` and `/spawn`, but sends no command graph,
so the vanilla client cannot validate/complete them locally. Publish these three
supported no-argument commands from a single catalog used by graph, help and
server dispatch.

- Mojang's 26.3 decoder reconstructs executable literal nodes.
- Actual-client completion suggests supported commands; `/sta` + Tab becomes
  `/stats`, executes and shows the response.
- `/help` matches the catalog, `/spawn` still teleports, and unknown names or
  extra arguments cannot dispatch a valid command accidentally.
- Argument parsers, permissions/plugins and full vanilla commands remain future
  work. The graph contains no advertised but unimplemented command.

## References and design

Inspected the pinned vanilla jar (`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`):
`ClientboundCommandsPacket.readNode/read/getRoot`, its `NodeBuilder`, and
`ServerGamePacketListenerImpl.parseCommand/performUnsignedChatCommand`. Private
bytecode dumps are under ignored `research/disassembly/`.

Compared Pumpkin `b0c48b2d7688` command tree/packet encoding in
`crates/pumpkin-command/src/node/tree.rs` and
`crates/pumpkin-protocol/src/java/client/play/commands.rs`, SteelMC
`f6fb4e49778c` in `steel-protocol/src/packets/game/c_commands.rs`, and Paper
`a2d844f71e27`'s Brigadier dispatcher patch. These confirmed indexed literal
nodes, executable/restricted flags, and the need to avoid advertising commands a
source cannot use. No upstream source was copied into the Elixir implementation.

The immutable catalog supplies graph, help and dispatch lookup. The graph is
encoded once at module compilation and shared; execution remains in the owning
connection. No global command process or per-command synchronization was added.
Mojang's reconstructed literal-only dispatcher rejects suffix whitespace and
unexpected arguments. An initial whitespace-trimming assumption failed the
oracle and was removed; raw packets now follow that exact literal grammar.

## Verification

October 13, 2026, Java 26.3 / protocol 777, production release on localhost:25565:

- Formatting passes; all 18 ExUnit tests pass, including exact literals,
  unknown names, case, trailing whitespace and extra arguments.
- Mojang's decoder reconstructs the graph and Brigadier executes all three
  literals, completes `sta` to `stats`, and rejects the invalid inputs. The TCP
  oracle passes registry loading, 49 chunks, two players, movement and block edits.
- Release builds and the public-tree audit/self-tests pass. No proprietary
  reference artifacts are included.
- Through computer use, reconnected the actual client and observed terrain.
  `/sta` + Tab became `/stats`; Return displayed player/region/scheduler metrics.
  `/` listed exactly help, spawn and stats; selected help listed all three.
  `/stats extra` and `/missing` produced `Unknown command. Use /help.`
- F3 showed X = -3.382 after strafing; `/spawn` restored XYZ 0.500 / 64.000 /
  0.500. The client remained connected and rendered the world.

One batched text-input attempt dropped characters and became ordinary chat. It
was not counted as a pass: retry used paste and screenshot verification before
submission. The client log has the expected disconnect from the server restart;
no new protocol error was observed. The running release produced no error output.
Only custom literal commands are covered; full vanilla command semantics remain
on the roadmap.
