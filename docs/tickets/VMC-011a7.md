# VMC-011a7 — Separate cold ownership admission from hot routing

Status: Done
Note: Done within admission/routing scope. October 15, 2026. Parent: VMC-011a.

Resource routes currently come from each region's process-name registration. That
cannot atomically reserve/reassign a set of resource keys during a domain change.
Introduce one cold admission directory, with protected ETS routes for hot reads.
Only starts/publications/deaths go through its mailbox; gameplay stays on owners.
Keep one resource per owner for this slice. Multi-resource handoff remains future work.

Acceptance:

- Race callers converge on one owner. Fence ready publication by admission token
  and PID; stale publication/DOWN cannot replace or erase another incarnation.
- Read-only owner/item observations never allocate or enqueue messages. Loading
  authority waits, with no partial publication; cold file I/O cannot block the
  directory or unrelated starts. Bound admission by the existing region limit.
- Infrastructure loss stops dependent owners before new routes can authorize work.
  A timeout alone cannot create a replacement for a live admitted owner.
- Preserve existing APIs/data, targeted world/item/recovery behavior and batching
  workload; verify actual-client edits/items/reconnect on a frozen checkpoint.

Next protocol, before coupled gameplay: directory-reserved operation token and
participant epochs; quiesce/settle sources; fence old cleanup; transfer writer
leases/data; publish target routes; retire sources. Controller/participant loss
must leave one fenced recovery path, never two actors resuming the same state.

Implemented: Directory admits via the existing bounded region supervisor, tracks
monitors directly and publishes protected ETS rows. Ready publication is one-use,
matching token/PID and a protected item table owned by that actor. World APIs use
those rows; Registry remains process naming only. Region load continuation keeps
disk I/O outside directory/supervisor handshakes. Rest-for-one ordering stops
dependent owners/writers/connections on directory loss; no live handoff yet.
