# VMC-026b4 — End gateways

Status: Awaiting client
Milestone: M2 real worlds
Depends on: [VMC-026b3](VMC-026b3.md).

End gateways carry players across the End as vanilla's do: the outer
islands' return gateways back to the main island, and a gateway without an
exit to the outer islands, building the exit gateway there.

Acceptance:

- A player in an end gateway is taken, within the End and keeping its
  rotation and motion, above the tallest block within 5 of 2 above the
  gateway's exit (bedrock excluded), or exactly to an exact exit (the outer
  islands' return gateways lead to (100, 50, 0)).
- A gateway without an exit, in the End, finds one as vanilla's
  `TheEndGatewayBlockEntity.getPortalPosition` does: 1,024 blocks out along
  its direction from the origin, back past chunks with blocks and forward
  past empty ones (16 chunks each at most), the spot in that chunk (or an end
  stone island raised at y 75 with vanilla's random for the position), the
  tallest block within 16, and a new gateway 10 above it whose exit leads
  back. Both exits persist.
- Each step equals vanilla's (`portals` stage), including vanilla's
  `findValidSpawnInChunk` returning its scan's last position whenever a spot
  qualifies (it keeps `betweenClosed`'s mutable cursor).

## Design

- `Valimc.Portal.Gateway`: the exit search, the tallest block, the arrival,
  `EndGatewayFeature`'s and `EndIslandFeature`'s blocks (pure; float
  arithmetic as vanilla's), with `Valimc.Portal.JavaRandom`
  (`LegacyRandomSource`, `BlockPos.asLong`).
- `Valimc.Portal.GatewayDestination` reads the entry gateway's exit from its
  region's preserved block entity, searches and builds when it has none, and
  records both exits.
- Region owners gain `Region.block_entity/2` and `put_block_entities/2`: the
  preserved set with the new entries is persisted whole in one frame through
  the store's group commit (`Store.commit_block_entities/5`, acknowledged as
  container writes), and the caller hears once it is durable. End gateways
  are placed as plain blocks; a chunk lists a gateway once, with its
  preserved data when it has some.
- `Valimc.Player.Portals` teleports within the dimension for a gateway (no
  respawn; vanilla's relative rotation and motion).

## Evidence

- `portals` stage, October 21, 2026: 40 gateway exits over sparse outer
  islands (22 spots found, 18 islands raised) equal vanilla's at every step:
  the tentative point, the spot, the island's blocks, the tallest block, the
  exit gateway's blocks and the arrival.
- `test/portal_connection_test.exs`: a creative player entering a gateway
  without an exit beside the main island arrives more than 700 blocks out
  next to a new exit gateway (bedrock below it); both gateways' exits are
  recorded, and the exit gateway leads back beside the first.
- Client run (VMC-026b): a placed gateway took the player out to (1028.5,
  71, -5.5) beside a new exit gateway, and that gateway back to (93.5, 57,
  -6.5) above the platform. A test on the same seed gives both exactly, with
  the exit gateway at (1028, 80, -7). It cannot be flown into (bedrock above
  and below, as vanilla's); the rerun enters it at its block.

## Limits

- A gateway's own 40-tick cooldown after a use and its beam (block event 1)
  are not kept; the player's portal cooldown still stops it bouncing.
- Thrown ender pearls and other entities do not use gateways.
- The main island's gateways appear with the dragon fight (M3); until then a
  gateway without an exit is one placed by commands.
