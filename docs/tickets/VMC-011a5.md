# VMC-011a5 — Isolate cold region loading

Status: Done
Note: Done. October 15, 2026. Parent: VMC-011a.

A region currently waits for its writer's disk reads inside `init/1`. The dynamic
supervisor waits for that handshake, so one cold file stalls unrelated region
starts. Use an OTP continuation after the handshake; load only that owner before
publishing its epoch/items or starting its simulation clock. Keep the ready-owner
lookup in Registry and make cold callers wait for readiness. No extra process or
hot-path coordinator is needed. The real FIFO regression also exposed `File.read`
serializing through OTP's shared file server; open region reads in raw mode so
one blocking open/read cannot hold unrelated file operations there.

Acceptance:

- A real blocked region-file read cannot delay an unrelated new region's reads,
  mutations or ticks. Concurrent requests for one cold region still converge.
- Never publish a partial resource or return its authority handle before load.
  Loading failure leaves its publication absent, its files intact and unrelated
  regions live; preserve typed diagnostics when the caller observes the exit.
  A caller racing an already-dead owner may receive `:region_restarting`.
- Keep existing APIs/data and bounded supervision. Calls/timeouts do not restart
  a live loading owner or start a duplicate. Existing ready lookups stay local.
- Target actual FIFO-stalled disk I/O plus affected owner/world/persistence tests.
  Measure concurrent cold-start isolation; retain raw workload/results privately.
- Dedicated tester: frozen checkpoint, join/terrain, ordinary edits, walk/reconnect,
  `/stats` and clean fresh logs. A separate trusted cold-file stall should leave
  the actual client's active region responsive. Preserve the whole test dataset.

This only isolates loading; it does not implement domain merges or transfers.

Implemented: load in `handle_continue/2`, after the supervisor handshake. Only
publish the resource and start ticks after successful loading. Cold authority
requests wait; ready lookups still use Registry. Failed loads can terminate with
an uninitialized resource safely. Block/item reads use raw local file access.

Verification: 65 affected loading/world/tick/batch/observation/item/recovery tests
pass. The actual FIFO regression fails against `a752ceb` because an unrelated
start cannot finish, and passes now; eight cold authority callers converge only
after real persisted bytes arrive. Corrupt block/item files remain intact and
unpublished. Formatting/diff/public audit pass; no broad suite/build repeated.

Same-driver five-load comparison: with each cold read stalled for 200 ms, median
unrelated cold-start latency is 201,624→163 µs; existing-owner reads are 36→38 µs.
The stalled owner's load remains 214 ms. This measures isolation under injected
I/O delay, not general server capacity. Raw workload/code hashes/results:
`bench/results/vmc011a5-{baseline,resource}.json`; reproduction logs:
`.local/vmc011a5-*`. Individual values/timing noise are retained there.

dataset. A real placement triggered a four-second far-resource FIFO stall; actual

Another new owner started immediately; the active owner kept ticking. Real saved
