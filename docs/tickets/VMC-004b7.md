# VMC-004b7 — Entity, block-entity, profile, book and sign data

Status: Done
Milestone: M4
Parent: [VMC-004b](VMC-004b.md). Depends on [004b4](VMC-004b4.md).

`entity_data` and `block_entity_data` (a type and its NBT), `bees`,
`profile` (name, id, properties and skin patch), `writable_book_content`
and `written_book_content` (filterable pages), `sign_text_front` and
`sign_text_back`, and the persistent-only `lock`, `container_loot`,
`debug_stick_state` and `recipes`, which never reach the network.

Acceptance: both formats round-trip in the `item_components` stage, with
the books' page limits, the profile's property limits and the entity data's
NBT budget enforced. After this slice no 26.3 component type is refused.

## Result (October 31, 2026)

Every one of 26.3's 122 component types now has a codec. The engine gained
UUIDs (16 bytes; four ints in the data form), player names, typed entity
data (a type and its compound; the data form holds the type under `id`),
fixed-size lists (no count on the network), filterable text (`{raw,
filtered}` or a bare value), resolvable profiles (a complete or partial game
profile beside the skin patch, or a bare name), int bounds (a point is one
number) and a debug stick's block => property map, which checks the property
exists. Fields written even at their default (`optionalAlwaysPresentFieldOf`)
are `{:present, default}`. `lock`, `container_loot`, `debug_stick_state` and
`recipes` never reach a client; their stream form is their data form as NBT.
A lock is an item predicate, with the same refusal of partial component
predicates as block predicates.

The `item_components` stage now fails on any type without a codec: 3,996
values of all 122 types round-trip both formats against Mojang. A delimited
creative component can no longer be "unsupported", so that correction path
is unreachable and its socket test is gone; a chest holding a writable book
now imports from a vanilla world as an owned chest (`anvil_content`).
