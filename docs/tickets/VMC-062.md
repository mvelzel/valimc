# VMC-062 — Rust NIF toolchain and paletted section storage

Status: Awaiting client
Milestone: M1 foundations
Depends on: none. Precedes VMC-063 (persistence v2) and VMC-065 (published reads).

Regions currently store blocks as a sparse `%{{x, y, z} => state}` map over a
hard-coded flat world, duplicated per chunk, capped at 131,072 edits per region
(about one real chunk). Chunk packets rebuild 4096-element lists per section and
filter the chunk's edits once per section. This cannot hold generated terrain.

After this slice each region owns its chunk columns as paletted sections in a Rust
resource, built by a reproducible local toolchain:

- `native/valimc_core`: pure Rust (no BEAM); paletted containers (single value,
  indexed 4–8 bits, direct 15 bits), 24-section columns, heightmaps from per-state
  masks, network section encoding. `cargo test` covers it.
- `native/valimc_nif`: thin Rustler shim, built and loaded by `use Rustler`.
- `Valimc.World.Blocks`: the owner-facing API (get, batch set, column heights,
  chunk section data, sparse export for the current persistence format). Region
  code uses it instead of `state.edits`/`by_chunk`.

Scope limits: persistence keeps the current sparse snapshot format (exported from
the sections) until VMC-063; light stays full-bright and biomes plains until M2;
the edit cap becomes a section-memory budget instead of an entry count.

Acceptance:

- Chunk packets are byte-identical to the Elixir encoder for flat, edited, mixed-
  palette (>16 states) and fully direct sections (parity tests over random edits).
- All existing world, mining, placement, chest, cooking and item tests pass.
- NIF calls stay under 1 ms for batches up to 4096 changes and one chunk encode;
  `bench/section_storage.exs` records encode time and memory against the old path.
- Malformed inputs (out-of-range coordinates or states) return errors, never panic.
- Milestone client baseline (with M1): join, terrain, mining, placement, chests,
  furnaces, items and reconnect.

Reference: vanilla `PalettedContainer`, `LevelChunkSection.write`,
`ClientboundLevelChunkPacketData` and `Heightmap` (26.3); bit packing per the
current Elixir encoder (`Chunk.longs/2`), which has passed vanilla TCP oracles.

Implemented (October 19, 2026):

- `native/valimc_core`: `Storage` (single / indexed u8 with palette compaction /
  dense u16), 24-section `Column`, `ColumnStore` per region with validation-first
  atomic batches, base-profile reads for untouched columns, a memory budget,
  vanilla section encoding (non-air and fluid counts, first-appearance palettes,
  4–8 bit indexed or global direct), heightmaps from per-state masks, chest
  lookup for block entities and sparse diff/compact. 9 `cargo test` cases.
- `native/valimc_nif`: Rustler 0.38 shim; `Valimc.Native` uses `use Rustler`
  (the `rustler` Hex package is a build-time dependency) to build and load it.
- `Valimc.World.Blocks` replaces `edits`/`by_chunk` in `RegionData`; durable
  proposals carry `changes` and are applied to storage on commit. Chunk jobs
  encode sections on the owner (a short NIF call) and assemble/compress in the
  worker. `ColumnIndex` takes a block lookup.
- Parity fix found on the way: the section header's fluid count was always 0 and
  cave/void air counted as blocks; both reference and Rust encoders now follow
  `LevelChunkSection.recalcBlockCounts`.

Checks: `test/blocks_test.exs` (randomized byte parity against the Elixir
reference for small, wide-indexed, direct and fluid/air palettes; flat fast path;
chests; atomic batches; bounds) and the full suite, 1,758 tests, pass. `cargo test`
and `cargo clippy` are clean. Benchmark (`bench/section_storage.exs`, medians):
one edit 3.7 ms → 0.10 ms, 4,096 edits 20.5 ms → 0.20 ms, terrain-like chunk
93.6 ms → 0.23 ms and 3.0 MB → 75 KB; untouched chunks unchanged at 1 µs.

All 176 vanilla oracle stages pass, including chunk packets decoded by the official
client codec over TCP. Next: the sparse persistence image and its 131,072-entry cap
remain until VMC-063; the client baseline runs with the M1 milestone handoff.
