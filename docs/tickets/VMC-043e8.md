# VMC-043e8 — Fish and axolotl buckets

Status: Awaiting client
Milestone: M3
Depends on: [VMC-043e2](VMC-043e2.md), [VMC-043e7](VMC-043e7.md),
[VMC-031a](VMC-031a.md).

Complete the aquatic family's remaining bucket interaction: a water bucket
catches a live cod, salmon, pufferfish, tropical fish or axolotl; using the
filled bucket pours water and releases that animal. The bucket retains the
modelled health, name, variant and axolotl age/age lock/hunting cooldown.
Released animals carry their from-bucket flag and survive ordinary despawning.

Acceptance:

- Capture and release data/components match native pinned 26.3 fixtures,
  including survival/creative inventory behavior and failed interactions.
- The existing hosted player/region callback commits the animal, fluid and
  held inventory together; stale or refused requests cannot duplicate them.
- Focused socket tests exercise actual item/entity requests, captured item
  persistence and release, including a section boundary.
- The batched client gate later catches and releases fish and an axolotl,
  retaining their visible variant/name. Client testing is deferred at the
  user's request; automated verification cannot close this graphical gate.

Reference: Mojang 26.3 server SHA-1
`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`, `Bucketable`,
`AbstractFish`, `Salmon`, `TropicalFish`, `Axolotl`, `MobBucketItem` and
`ItemUtils.createFilledResult`. Private bytecode observations stay under
`.local/m3-buckets-javap.txt` and `.local/m3-bucket-itemutils-javap.txt`.
The native bucket uses current variant item components, not legacy variant
fields in entity NBT. Capture uses the four-argument filled-result behavior,
which also differs from ordinary water pickup for creative inventories.

## Implementation and automated evidence (October 24, 2026)

`Entity.Bucketable` makes the item data and restores the body; generated
`Data.BucketFacts` owns native bucket types, variant names and wire ids.
`Protocol.ItemStack` and `ItemData` retain both network components and the
native data-format enum strings. Capture runs before ordinary animal food
use; removal, lead drops, pickup sound and the filled hand settle in the
existing hosted callback. A second request cannot capture the removed UUID.
Creative capture keeps its water bucket and attempts another filled bucket,
even when one is already present; a full creative inventory discards that
result, as native `Inventory.add` does.

Release preflights the existing entity admission before the fluid operation,
reserves an ordinary network id, then retains the operation's entity effects
and admits the animal only after a successful pour. Refusal changes no animal,
inventory or AI random. Placement uses the constructor-sized collision box,
reading authoritative sibling sections too. Spawn yaw and finalization run
before the saved components/tag; axolotls skip finalization for `BUCKET`,
as native does. The from-bucket flag supplies custom despawn persistence;
the axolotl brain now saves its hunting cooldown.

Stage `bucket_mobs` passes 606 native capture/release cases with network and
data-format round trips, sixteen survival/creative main/offhand inventory
cases, fifty collision placements and sixty spawn yaw/level-random cases.
The affected test files pass 33 checks; one socket scenario captures a named,
large salmon across a section boundary, reconnects with the bucket, rejects
stale/denied requests, releases one animal and rejects recapture of the old
UUID. The existing despawn scenario also distinguishes wild and bucketed fish.
Private evidence: `.local/m3-bucket-parity.log`,
`.local/m3-bucket-targeted.log` and `.local/m3-bucket-release-recheck.log`.
The final source passes all 102 affected vanilla stages in 269 seconds,
with 109 cache hits, five new native extractions and no unverified stage
(`.local/m3-bucket-changed.log`). The earlier pre-ordering run is retained
in `.local/m3-bucket-changed-before-post-pour.log`. The completed socket
scenario also pours into four-layer snow and verifies release at the
post-pour water height (`.local/m3-bucket-post-pour.log`); it exercises a
solid-target refusal without changing inventory, animals or AI random.
Formatting and the publication/layer audit pass. No Rust code changes.

No actual-client test has run for this slice. Its graphical gate stays
pending at the user's request. This does not add shared silent, glowing or
invulnerable mob semantics: a bucket explicitly requesting those flags is
refused intact. VMC-031a's existing pour-sound/statistics limits also remain.
