# VMC-043e22 — Player attack-speed attributes and cooldown display

Status: Awaiting client
Milestone: M3
Depends on: [VMC-043e21](VMC-043e21.md).

The client needs the same attack-speed attribute that the server uses for attack
strength. Derive it once from the held weapon and active effect amplifiers, and
publish changes on login, held-item changes, effect changes and respawn.

Acceptance: native player attributes match values and modifier identities for
stock weapons, bare hands and relevant effects; socket sessions receive initial
and updated values, including resets. The server's strength calculation uses
the same result. Actual-client testing remains deferred at the user's request.

Reference: Mojang 26.3 server SHA-1
`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`, `Player.createAttributes`,
item main-hand modifiers, `MobEffects`, `AttributeInstance.calculateValue` and
`ClientboundUpdateAttributesPacket`.

Deferred client scenario: compare the cooldown indicator with bare hands, a
sword and an axe, then while under Mining Fatigue and after it expires.

Implementation: `Living.Attributes.attack_speed/2` supplies one protocol
attribute and its value. Player attacks and attribute replication consume the
same result. The session caches the derived attribute, so duration-only effect
ticks and irrelevant inventory changes do not resend it. Login, equipment,
effect application/removal/expiry and respawn use the existing publication paths;
respawn invalidates the cache when the client resets entity attributes.

The native comparison also established that Haste contributes an attack-speed
modifier; the earlier server calculation included only Mining Fatigue. Native
total multipliers evaluate Mining Fatigue before Haste. Both effects now match
that order. When high Mining Fatigue clamps speed to zero, native's delay is
infinite and its strength remains zero. The melee helper represents that delay
as `:infinity` and handles zero-speed strength/minimum charge without dividing
by zero.

Validation: 720 native attribute cases cover twelve stock items, both hands,
Haste and Mining Fatigue amplifiers, modifier identities and exact double values.
The actual native player methods also match 7,200 strength samples and minimum-
charge decisions, including zero speed. All 37 affected combat, equipment,
item-use, food, effect, lifecycle and socket tests pass. Socket checks observe
login, hotbar switching, combined effects, expiry/removal, reconnect and respawn
resets. A sword attack at zero speed deals its weak damage and leaves the
connection alive. Six affected native stages pass; the final attack-speed,
combat, packet and TCP stages pass again after adding the zero-speed boundary.
Evidence: `.local/m3-attack-speed-{native,check,tests,final-tests,stages,final-stages,audit}.log`.
