# VMC-014c3b2b2 — Live player-owned pose selection

Status: Done
Note: Done within live block-based pose selection scope. October 15, 2026. Depends on VMC-014c3b2b1 and VMC-011a7.

Select and replicate standing/crouching/swimming-height poses from live block
occupancy, replacing input-only flags. The existing player process commits its
pose; one bounded geometry job per player uses the shared bounded worker pool.

Acceptance:

- Sample complete existing-owner block observations, perform native lazy pose
  selection, then recheck all source epochs/revisions. No cold allocations,
  invented missing geometry or cross-owner transaction/atomicity claim.
- At most one job and one latest input/environment signature per player. Discard
  late results after movement/input/world changes. Owner loss, timeout or pool
  saturation retains the previous selected pose and allows an independent player
  to progress; disconnect cancels work. Unchanged stationary state does no work.
- Publish selected pose metadata to self/peers, initialize late/recreated observers
  and use selected eye height for block interaction distance. Preserve flags.
- Test open space, Shift, crouch-only/crawl-only ceilings, standing recovery,
  stale computations, concurrent players and source failure. Compare pose metadata
  with pinned native codecs, plus affected connection/geometry regressions.
- Dedicated actual client: ordinary movement/Shift, low-ceiling retention/recovery,
  block interaction, commands/reconnect and fresh logs on an immutable checkpoint.

Reference: pinned 26.3 `Player` pose selection/dimensions (prerequisite native
fixtures), `Entity.DATA_POSE`, `EntityDataSerializers.POSE` and native metadata
codec. Scene has no solid entities or live movable border yet; block-entity-backed
dynamic shapes remain explicit observation failures. Swimming-height fit is not
water swimming, and this slice does not add movement collision enforcement.

Ordering: player state/input → sampled geometry → source revision recheck →
player signature check/commit → publication. Block events invalidate the sample
and schedule a new fit. This preserves independent player ownership; future
coupled effects require their own ordered mutation protocol, not speculative
region merges as a prerequisite for this feature.

Implemented: one 250 ms job per player, latest signature only, source monitors
for idle invalidation and no repeat work for unchanged stationary state. Source
revisions are rechecked after computation; the player rejects expired results,
changed signatures and replaced source owners before committing. Selected pose
metadata initializes self/late/recreated peers; reach uses selected eye height.

Checks: 113 affected geometry/input/connection/inventory/recovery tests pass,
including four-owner source changes/replacement, stale intent, a result expiring
in a suspended player's mailbox, pool saturation, independent-player progress
and disconnect cancellation. Native entity codecs verify 272 packed velocities
and 43 packets, including all 18 poses; targeted plaintext/encrypted TCP passes.
Logs/fixtures: `.local/live-pose-{affected,native,native-tcp}*`.

Measurement: `bench/player_pose.exs`, three 400-query runs per mode, equal
open/Shift/crouch/crawl mix, warm geometry, 1/16 owners, concurrency 1/10.
Mac 16,1, 10 schedulers, 24 GiB, pinned Elixir/OTP: serial median latency 88/93 µs;
concurrent median 223/218 µs and p95 346/357 µs. This measures sampled geometry
only, without network/survival or a full-server capacity/speed claim. Raw samples,
inputs/script and implementation hashes: `bench/results/live-pose-20261015.json`.

full-ceiling crawl-height camera followed by standing recovery/movement. Native
pose metadata 5/0/3 and source state matched; actual F2 images are labeled/hashed.
Report: `.local/client-tests/VMC-014c3b2b2/report.md`. All 375 archive blobs and
