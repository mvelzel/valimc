## Scope and acceptance

Before: `container_close` only repeats the authoritative cursor/slots, leaving a
carried stack outside the inventory after the menu closes. After: a connected
player's menu close returns supported carried/grid contents when they fit.

- A pure bounded return plan cancels a gesture, consumes cursor first and then
  crafting input slots 1..4 in order, clears virtual result slot 0, and preserves
  exact accepted item components/removals. No recipes or crafting clicks are added.
- Merge order is selected hotbar, existing offhand, then inventory storage in
  vanilla inventory-index order (hotbar 36..44, main 9..35). Empty destinations
  use that same storage order and never auto-equip armor/offhand. Item caps and
  vanilla stackability apply. Returning does not invoke item click overrides.
- The plan exposes overflow stacks as effects rather than losing or creating
  items. Full/partial capacity remains a required world-drop boundary in the
  parent ticket. Until that owner handoff exists, the connection rejects the
  entire overflowing close, restores its old slots/cursor and explains the
  limitation. No partial return is committed before a drop can be accepted.
- Aggregate byte limits apply atomically after returning potentially split
  stacks. Menu close cancels pending drag even on rejection. Unknown container
  handling follows the pinned listener; malformed frames remain isolated.
- Regression tests cover selected/offhand priority, storage ordering, caps,
  incompatible patches, non-stackable damageable items, grid cleanup, idempotence,
  overflow conservation, atomic byte rejection, peer isolation and malformed close.
  Extend the actual Mojang inventory-method harness and official-codec TCP oracle.

Actual-client scenario, Java 26.3 via CUA: seed bounded patched source stacks and
ordinary player-menu UI through development fixtures; perform actual pickup,
close/reopen and inspect the returned stack, cursor and owner state. Exercise
selected/offhand merge priority, empty-hotbar placement and full-inventory
rejection with contents retained; make space and retry. Restore creative UI.
Fixtures do not count as the changed close action. Record client log review.
