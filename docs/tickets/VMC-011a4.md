# VMC-011a4 — Separate storage resources from simulation ownership

Status: Done
Note: Done — resource extraction slice. October 15, 2026. Parent: VMC-011a.

Keep bounded storage-region data/writers, but let a simulation owner eventually
hold several nearby resources. A fixed file-grid boundary must not imply that
coupled entities/blocks can simulate independently. Preserve the vanilla player
experience, freely using BEAM ownership and measuring the result.

Reference/design evidence: pinned Folia `acf6733`, `ThreadedRegionizer.addChunk`,
`tryMarkTicking`, `markNotTicking` and merge callbacks; membership changes occur
outside active ticking, with nearby ownership reserved before admission.
Dragonfly `1793369`, `server/world/tx.go`, scopes mutable access to owner callbacks
and batches structures. These inform invariants, not a translation of Java locks
or Go transactions.

First implementation slice:

- Extract bounded resource state from the region process's lifecycle/timer state.
  Initially retain one resource per owner and existing public APIs. This should
  be a real runtime refactor with existing behavior preserved, not unused actors.
- Route resource epochs, worker replies and writer failures explicitly. Future
  multi-resource dispatch must use direct indexes, not scan every resource.
- Preserve item journals/receipts, block revisions, encoder invalidation and shared
  binaries. Verify current targeted tests/probes and a comparable batch workload;
  delegate actual edits/items/reconnect on an immutable checkpoint.

Current slice: one `RegionData` value under the existing owner, with owner-local
tick state outside it. Tag resource timers/worker/writer replies with its epoch;
block-save replies also identify their writer. Reject stale/untagged resource
callbacks. Keep the public owner handles, file formats and process count unchanged.
Actual-client gate: block batch create/clear, ordinary edits, durable patched scene
item create/remove, reconnect, `/stats` and fresh logs; preserve the whole dataset.

Subsequent integrated topology protocol, before live simulation:

1. Cold directory changes membership; hot routing uses ETS, not a global gameplay
   call. One actor owns all mutable state in an admitted coupled domain.
2. Quiesce source callbacks/ticks and settle pending durable writes; prepare target
   state/writer ownership, publish new fenced routes, resume target, retire sources.
   Neither timeout nor controller loss may blindly resume both copies.
3. Merge/split only between mutation phases. Bound resources, queued work and
   transfers; stale input/worker replies must fail their owner/resource epoch.
4. Define participant failure/recovery and test races before activating transfers.
   Sequential revision checks and published observations do not grant atomicity.

Exact domains, failure protocol and APIs remain implementation decisions. This
ticket does not declare topology, handoffs or player authority implemented.
