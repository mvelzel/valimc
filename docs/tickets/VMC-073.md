# VMC-073 — The full suite passes on a loaded host

Status: Done
Milestone: M2 real worlds (gate for the milestone run)
Depends on: [VMC-070](VMC-070.md) (view distance 2 in tests), [VMC-071](VMC-071.md).

Several sessions run CPU-heavy oracle suites on the same Mac, so the host often
sits at a load average of 40–70 on ten cores. Under that load `mix test.fast`
lost 12–30 async region tests per run and the socket suites about ten, though
every one of them passed alone and on a quiet host; the unchanged tree failed
just as often. For the M2 milestone run the full `mix test` has to be a reliable
gate.

Reproduction: twenty busy-loop shell processes (`while :; do :; done`) beside the
run, which kept the load average near 50–85. A compile into the same build mid-run
replaces modules under the running suite (one such run lost 533 tests to "module
not available"), so loaded runs used a frozen copy of the tree with its own build.
The deliberate extra load slowed the other sessions on the host, so it is not part
of the acceptance and should not be used again.

Scope: make each such test deterministic without weakening what it checks — wait
on the condition rather than a count of short sleeps, drive game time explicitly
instead of wall time where the test means ticks or deadlines, and give test-side
bounds generous ceilings that a passing run does not wait for. No test measures
performance, so none needed moving out of the default suites.

Acceptance:

- Two consecutive runs of the full `mix test` pass on the shared host, without
  deliberate extra load.
- Production timing is unchanged: every new knob defaults to the play value.

Findings and fixes:

- Owner call budgets. Region API calls had 250 ms (and 1–7 s) `GenServer.call`
  budgets, and the item requests carry `now + 250` deadlines; a loaded owner
  answers later, so callers exited (`reserve_placement`, `reserve_mining`,
  `observe_blocks`, `World.owner`, `PlayerStore.close_session`). New
  `owner_call_scale` (1 in play, 20 in tests) multiplies those budgets and
  deadlines, `World.owner`, directory admission, the player store's calls and the
  250 ms pickup and item-merge permit lifetimes (`Valimc.Txn.Permits`). It is read
  per owner (`Valimc.config/2`), so a test pins one owner back to 1. The same scale
  applies to the item-merge donor's contact window, the widest chest, table and
  cooking grant and creative destruction an owner accepts (`Permits.window/2`), the
  cross-merge job's deadline, the placement plan's budget (`PlayerPlacementQuery`)
  with the widest placement deadline an owner accepts, and the grants a connection
  issues: placement, creative destruction, container and table contexts and motion
  admission (read per player UUID). Grants a test builds itself use
  `TestRegion.grant_expires/1`. Tests that exercise a timeout pin the scale
  (`block_observation_test`, `placement_owner_test`, the pure permit, chest and
  cooking grant tests, two motion and two placement tests that outlast the window)
  or fire the deadline explicitly (`item_cross_merge_auto_test`).
- Expiry by sleeping. Tests that slept 260 ms past a 250 ms deadline now expire it
  explicitly while the request is in flight: `TestRegion.expire_held_replies/1`
  (grants answered once a write is durable) and `TestRegion.expire_permits/1`
  (pickup and merge permits). That removes the sleeps and the race in which a
  slow host delivered the request after its deadline (`pickup_region_test`,
  `item_cross_merge_region_test`, `item_cross_merge_auto_test`,
  `player_pickup_connection_test`).
- Polling helpers. Seventy per-file `wait`/`eventually`-style helpers (and
  `TestClient.await_position/3`) bounded a condition by a count of 1–20 ms sleeps
  (0.2–5 s in all). They now delegate to `Valimc.TestWait.until/2`, which polls
  until a 30 s wall-clock deadline and returns as soon as the condition holds; each
  keeps its return contract.
- Item simulation stepping. `item_simulation_region_test` stepped manual owners
  one tick per millisecond for 600 tries while simulation workers had not
  reported; each step now waits until the neighbourhood's in-flight simulation has
  finished, so a step always simulates.
- Player ticks. Tests that "park" the player clock and send ticks by hand still
  got wall-clock ticks: before the park, and after every manual tick, which
  re-armed the timer. New `player_ticks: :manual` (scoped to the player's UUID)
  never arms the timer; the eight such socket modules use it (freeze, fire, void,
  air, food, use, periodic, movement food).
- Receive and task bounds. The global `assert_receive` timeout went from 1 s to
  15 s and 201 explicit 1–6 s windows now use it; 78 `Task.await`/`async_stream`
  calls on the 5 s default (or 1–5 s explicit) got 60 s; the test client's socket
  reads and connect allow 30 s. A passing call still returns at once.
- Stats barriers. Socket tests sent `/stats` and took the next system chat as its
  reply. Join and leave lines are system chat too, so a peer's join line could end
  the barrier before the earlier packets were handled. `TestClient.barrier/1` and
  `await_stats/1` wait for the stats reply itself (58 sites), reading up to 5,000
  packets as the menu-overflow barrier did.
- Login listing. A client sees its position packet before the player is listed in
  `Players`; `TestClient.login_session/2` now returns once it is.
- Teardowns. Since view distance 2 a player loads its neighbouring regions, and a
  respawn loads the spawn's. Teardowns stopped only the test's own region, so the
  others kept writing into the removed world (`File.rm_rf!` raced them) and could
  serve the next test. `TestScope.stop_neighbourhood/2` stops them gracefully
  before removal (26 modules; socket modules include the spawn regions), and
  `TestScope.stop_players/1` stops the connections and player stores writing under
  the test's world, since a store writes the player file when its session closes
  (every socket module that removes its world).
- Settle before acting. Contact and environment queries read the published
  snapshot, which follows a durable edit once the owner is quiescent:
  `TestRegion.set_published/2` and `await_published/2` wait for it (fire, air,
  freeze, periodic and movement-food tests). The air test also spends a frame
  sampled just before its stall, and `set_published/3` waits until the connection
  has seen a mid-test edit, which drops geometry it sampled earlier. Grants a test builds itself start once the owner
  has no write in flight, one per admission; a writer is broken only once nothing
  else is being written (two writer-failure tests in `placement_region_test`); a
  relogin waits until the old player store has closed or is handing over.
- Individual races:
  - `region_tick_test` held the deadline but not the timer armed at load; it now
    cancels it and takes a fresh token.
  - `cooking_orb_runtime_test` checked a 1 s backoff with a wall-clock tick (it now
    ticks just before `retry_at`) and compared a restored owner's orb views before
    it had published them (it now waits for the publication).
  - `cooking_region_runtime_test` retries a flush answered busy, and
    `disconnected_inventory_test` an item removal answered busy while the player
    store's delivery is being written.
  - `connection_test` sums the sender's coalesced movement deltas instead of
    expecting one packet.
  - `player_fire_connection_test` waits until collision readers' published
    snapshot shows its block edit; `item_cross_merge_region_test` waits for the
    durable clear.
  - `placement_owner_test` takes a fresh placement deadline after slow setup and
    expires its queued commit with an explicit 50 ms deadline.
  - `player_pickup_connection_test` steps its item from the revision the owner's
    own ticks reached.
  - `player_motion_connection_test` takes the queued input's token from its retry
    message (traced) instead of polling the brief queue, ends each attempt on its
    correction, and tries again when a descheduled connection let the input expire
    before it queued.
  - `player_pose_connection_test` reads the connection once per check (two reads
    raced a finishing job).
  - `item_checkpoints_test` read the armed checkpoint token after the owner's own
    1 s timer could already have fired; the new scoped `item_checkpoint_ms` (1000 in
    play) is an hour there, so only the test's triggers checkpoint.
  - `view_distance_connection_test` bounds the first batch by vanilla's start rate
    (at most 9) instead of expecting exactly 9, since chunks of a loading region
    wait for a later batch, and reads the login packet's dimension list (VMC-026b1).

Results:

- Two consecutive full `mix test` runs on the shared host (load 22–40 from other
  sessions): 1779 passed (9 properties, 1770 tests) each, in 249 s and 261 s.
- Earlier runs with deliberate extra load (load 60–90): the fast suite went from
  12–30 failures per run to none, and full runs reached 1779/1779; each found a few
  rarer races, fixed above, until the extra load was dropped.
