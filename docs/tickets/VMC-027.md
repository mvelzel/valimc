# VMC-027 — World border and spawn search

Status: In progress
Milestone: M2 real worlds
Depends on: [VMC-027a](VMC-027a.md) (border geometry), [VMC-024](VMC-024.md)
(generated terrain), [VMC-053](VMC-053.md) (command tree).

The preview had a fixed, invisible default border and spawned new generated
worlds on the surface at the origin. Vanilla 26.3 keeps one border per
dimension as saved data (`world_border`), ticks a moving border once per game
tick, sends it to players on join and on every change, damages players outside
it, and changes it with `/worldborder`. A new world's shared spawn comes from
the noise settings' spawn target and the generated chunks around it; players
then spawn within the respawn radius of it.

## Design

- **Owner.** Borders are environment state: `Valimc.World.Clock` owns one
  `Valimc.World.Border` per dimension (the overworld today), ticks it before the
  weather on each game tick, saves it with the clock record (version 5, the
  settings vanilla's codec saves) and publishes it in its ETS table with a
  physics view (collision snapshot, safe zone, damage per block).
  `/worldborder` changes run in the owner (`Clock.border_command/2`), so their
  checks and the change are atomic; vanilla runs them on the server thread.
- **Moving borders.** Vanilla's moving extent counts remaining ticks and
  interpolates from the start size; its bounds use the previous step's size
  (partial tick 0). `Border.snapshot/1` gives collision that previous size, so
  the stationary geometry of VMC-027a is reused.
- **Replication.** Each change stamps its kind (centre, size as set or lerp,
  warning time, warning distance), as vanilla's border listener does. A
  connection keeps the border it last sent and, on its 50 ms publish tick,
  sends the packet of each changed kind built from the current state; join
  and respawn send the full state. A lerp observed a tick late carries the
  current size and remaining ticks, which the client continues identically.
- **Damage.** `LivingEntity.baseTick`: outside the border (the player's box
  must be inside, with vanilla's corner epsilon) and beyond the safe zone, the
  player takes `max(1, floor(-(distance + safe zone) × damage per block))` as
  `outside_border` damage (armour ignored; Resistance and Protection apply).
  Vanilla checks suffocation first; ValiMC has no suffocation yet.

## VMC-027b — the border live (October 21, 2026)

`Valimc.World.Border` (pure kernel), `BorderReplication` (packets), the clock
owner's border state and record version 5, connection join/respawn/publish
replication, `Vitals.apply_border_damage/1`, and the live snapshot in player
pose, movement and item collision. Default border: centre 0, size 59,999,968,
damage 0.2 per block, safe zone 5, warning 5 blocks and 300 ticks.

Known differences: imported vanilla worlds start with the default border (the
original `world_border.dat` is preserved for export, not read into play);
border packets of a change reach a player on its next 50 ms publish tick, not
in the same tick.

## VMC-027c — `/worldborder` (October 21, 2026)

`Valimc.Commands.WorldBorder`, registered for the vanilla tree's ten
executable paths (permission level 2). `Vec2` arguments parse with
`minecraft:vec2` and become floats as vanilla's `Vec2` does; numbers are
formatted like `String.format(Locale.ROOT, "%.Nf")` (shortest digits, half
up). `add` without a time is immediate; with a time it adds to the remaining
ticks.
