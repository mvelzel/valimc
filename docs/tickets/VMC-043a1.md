# VMC-043a1 — Selectors over items and orbs

Status: Done
Milestone: M3
Depends on: [VMC-043a](VMC-043a.md) (bodies and their selection).

VMC-043a's client run found `/kill @e[type=item]` answering "No entity was
found" beside dropped rotten flesh: entity selectors picked players and
bodies (mobs and objects) only. Vanilla's `@e`, `@n` and the rest select
every entity in the level, dropped items and experience orbs included.

Acceptance:

- `@e`, `@n` and `@e[type=item]` or `@e[type=experience_orb]` match items
  and orbs with vanilla's type, distance, box, limit and sort options.
- `/kill` removes a selected item or orb; `/teleport` moves one through its
  owner, as item physics moves it across section and group lines.
- Feedback names an item by its item name and an orb as an experience orb.

## Implementation (October 23, 2026)

- **Selection.** `World.entities/2` reads every non-player kind from the
  sections' published views (`World.bodies/1` keeps mobs and objects).
  `Commands.Targets` turns an item view into a body of type `minecraft:item`
  and an orb view into one of `minecraft:experience_orb`, with the type's
  size for box options, so type, type tag, distance, box, limit and sort
  apply as to any body. An item's view carries its stack's `item_name`
  (`ItemEntity.getName`), which `Source.display_name/1` uses.
- **Kill.** `Store.kill/2` already removed any entity that is not a mob.
- **Teleport.** `Store.teleport_step/5` builds the move step by kind: a body
  turns to its rotation; an item or an orb keeps its saved motion with zero
  velocity and on the ground, as `TeleportCommand` leaves an absolute
  teleport's target (its delta is zeroed on absolute axes, then vertically).
  The item step then moves it as item physics does: in its section, to a
  sibling in the group commit or by the durable handoff. Before, the step
  lacked the motion item and orb steps require and the move failed.
- Not modelled: a teleport with relative `~` horizontal coordinates keeps the
  target's horizontal velocity in vanilla; ValiMC zeroes it like an absolute
  one.

Reference: 26.3 `TeleportCommand.performTeleport`/`getRelatives`, `Relative`,
`ItemEntity.getName`, `ItemStack.getItemName`, `KillCommand`.

Checks: `mix test test/entity_bodies_test.exs` (items and an orb picked by
type, distance, sort and limit; `/tp` of the nearest item and `/kill` of an
item, an orb and the rest; the earlier body test now excludes the zombie's
dropped loot from `type=!player`), with the combat, command, item, loot and
region suites over the changed modules (52 tests); `check_vanilla.py
--changed` 21/21.

Client scenario (with the phase's handoff): in creative, kill a zombie or
drop items, then `/tp @e[type=item,sort=nearest,limit=1] ~ ~ ~3`: the nearest
item moves 3 blocks south and the chat names it. `/kill @e[type=item]` removes
every dropped item ("Killed N entities"); `/kill @e[type=experience_orb]`
removes orbs.

## Client run (October 23, 2026; frozen `1b72b467` release, fresh worlds; `.local/client-tests/M3-run-2/run-02`)

Passed: with a dropped bow and snowball,
`/tp @e[type=item,sort=nearest,limit=1] ~ ~ ~3` answered "Teleported Bow to
40.5, 64, 3.5" (3 blocks south), and `/kill @e[type=item]` "Killed 2
entities". Orbs from a zombie the player killed went with
`/kill @e[type=experience_orb]` ("Killed 2 entities"). `/summon
experience_orb` is not supported yet.

The run found `@e[name=Bob]` matching player names only, not a zombie named
Bob by a name tag. Fixed after the run: a selected body carries vanilla's
`Entity.getName()`, its custom name, else an item's name
(`ItemEntity.getName`) or its type's, and `name=` matches that name's plain
English string, so `name=Bob`, `name=Zombie` and `name=Stone` pick as vanilla
does. Command feedback names a named mob by its name ("Killed Bob").
`test/entity_bodies_test.exs` covers a name tag's name, a type's name and an
item's.
