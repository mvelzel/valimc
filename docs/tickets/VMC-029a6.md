# VMC-029a6 — Live basic survival mining

Status: Live composition automated-verified; graphical gate pending.
October 16, 2026. Parent: [survival mining](VMC-029a.md).

Acceptance: unmodified clients mine ordinary stone, dirt/grass, cobblestone,
planks and glass with current stock tool/gear speed, harvest permission, loot and
wear. Compose the existing player clock, fresh eye/ground observations, renewable
original-block permit and durable source/destination receipt protocol. Keep one
attempt and one bounded query per connection; socket owners never wait for disk
or region calls. Abort, changed block/owner, lost reach, loading, death, relocation
and stale callbacks cannot authorize a replacement block. Publish changed cracks
to peers and correct failed client predictions.

This first live slice admits explicitly supported plain blocks; it does not
silently substitute base removal for specialized destruction callbacks. Broader
blocks/loot, effects, statistics, experience, mining exhaustion and item entity
physics remain separate work. Once a source intent is durably admitted, complete
or compensate it using receipts even after disconnect/death.

Client scenario: punch dirt; mine stone with a pickaxe and without a harvest tool;
abort/restart, change tools, leave reach and let another miner win. Check glass
with/without Silk Touch, a final-use tool, exact drops/wear and fresh reconnect.
Actual GUI checks belong to the dedicated tester on an immutable release.

The socket owner retains one attempt and at most one250ms region task on the
bounded collision pool. Reservation renewals run only after world changes or
every5 seconds; unchanged ticks use immutable facts and fresh, fenced eye-water/
ground observations from the existing geometry lane. A still-live original token
survives long mining without granting credit to target ABA or a new region owner.
Task deadlines are checked again when results leave a delayed player mailbox.
Cancelled orphan reservations expire within10 seconds if early release cannot run.

Completion samples loot with the original selected tool, then wear and item UUIDs
once. The source journal precedes destination delivery; existing receipts finish
or refund exact wear. An ordinary pending player save holds a ready attempt,
without cancelling it or sampling RNG. Committed equipment and block updates use
the existing replication paths; failed predictions get a bounded fresh block read.
Nearby peers receive changed visible cracks and clears. No new global tick owner.

Targeted TCP checks cover timed stop, final-use Silk Touch, bare-hand no-loot,
abort/ABA/relocation/death, slower tool selection/early stop, competing sources,
peer cracks, saved reconnect, stalled saves/regions and retired/expired callbacks.
All10 new scenarios pass across the final targeted runs, alongside65 existing
source/region, motion/pose, plain-food and equipment regressions. Deadlines were
rechecked after adding the suspended-mailbox regression; no broad rerun per edit.
Initial failures were test fixtures: no accepted ground packet, reversed snapshot
decode arguments, render observations mistaken for item records, and the damage
API's returned outcome. Corrected fixtures inspect durable records and real packets.
Logs `.local/live-mining-{compile,affected-tests,tests-with-deadline,deadline-verified}.log`.

Remaining: actual-client scenarios above, coherent full tests/native integration/
production build, then publication. This is a limited basic-block implementation;
the broader survival-mining parent remains open.
