# VMC-020 — NBT and versioned world schemas

Status: Foundation
Note: Nothing reads world files in play yet; Anvil import (VMC-021) is the first user.
Milestone: M2 real worlds
Depends on: M1. Feeds [VMC-021](../backlog.md) (Anvil chunk/entity/region storage).

ValiMC's only NBT codec is the network one used for items and text
(`Valimc.Protocol.NBT`): unnamed root, a 64 KiB / 1,024-node / depth-32 budget, and
duplicate names refused. Vanilla world files need a named root, gzip or zlib
framing, far larger trees and vanilla's depth limit, and every world file carries
a `DataVersion` that decides which schema it follows. Nothing reads or writes them
yet.

Scope: one bounded NBT codec for both network and disk framing, with compression;
a schema layer that identifies world file kinds and their data version. Region
files (sector tables, chunk headers, external `.mcc` chunks, LZ4) and converting
chunk NBT into section storage are VMC-021.

Acceptance:

- One codec, `Valimc.NBT`, with explicit per-call limits (input bytes, inflated
  bytes, nodes, depth). Network framing (unnamed root) keeps today's protocol
  limits and duplicate-name refusal; disk framing reads a named root (the name is
  skipped, as vanilla does) and writes the name `""`. Disk reads use vanilla's
  depth limit of 512 and its duplicate rule (the last value wins).
- gzip (`level.dat`, player and `data/*.dat` files), zlib (region chunks) and
  uncompressed framing; inflation stops at the output limit (no decompression
  bombs), and trailing bytes are refused.
- Malformed or hostile input returns `{:error, reason}`, never raises or
  allocates without a bound: truncation, unknown tag ids, negative lengths,
  `end`-typed non-empty lists, invalid modified UTF-8, excessive depth, node or
  byte counts. Property tests mutate valid inputs.
- Golden vanilla round trips: an oracle runs the pinned 26.3 dedicated server to
  produce a real world. ValiMC decodes every NBT payload (level.dat, every region,
  entity and POI chunk, `data/*.dat`) to the same value as vanilla (a canonical
  digest computed independently on both sides) and re-encodes it so that vanilla
  reads back an equal tag.
- Differential edge cases: vanilla's verdict (accept with value, or reject) on
  synthetic inputs (every tag type, modified-UTF-8 edges, depth 512/513, duplicate
  names, truncations) matches ValiMC's, with documented divergences only.
- Schema layer: classify world files by kind, read their `DataVersion`, accept
  only the pinned one (5023) and refuse missing, older or newer versions with
  distinct reasons (upgrading older worlds is VMC-028).
- Elixir or Rust is decided by a matched benchmark on the golden chunks, recorded
  here.

Reference: pinned `net.minecraft.nbt.NbtIo` (`readUnnamedTag` skips the root
name; `readCompressed`/`writeCompressed` use gzip), `NbtAccounter` (depth 512;
quotas of 2 MiB for network, 100 MiB `uncompressedQuota` for `level.dat`, and
unlimited for region chunks via `RegionFileStorage`), `CompoundTag` (hash map,
so a repeated name replaces the earlier value), `DataInput.readUTF` (modified
UTF-8).

Progress (October 20, 2026):

- `Valimc.NBT` (was `Valimc.Protocol.NBT`) is the one codec. Network framing and
  its budgets are unchanged for callers (32 levels below the root, now counted as
  containers like vanilla). Disk framing: `read/2`, `write/2`,
  `read_compressed/3`, `write_compressed/3`, `decompress/3`, `compress/2`, with
  `disk_limits/0` = 64 MiB, 2,000,000 nodes, 512 containers, last name wins.
  Inflation stops at the byte limit, and a stream that ends early is refused
  (Erlang's `safeInflate` reports `:finished` once the input is consumed, so
  `inflateEnd` checks that the stream actually ended).
- `Valimc.World.Schema`: kinds by path (`level.dat`, `players/data`, `data/*.dat`,
  `region`, `entities`, `poi`) and `check/2`, which reads `DataVersion`
  (`Data.DataVersion` in `level.dat`) and accepts only 5023, with
  `:missing_data_version`, `{:older_data_version, v}` or `{:newer_data_version, v}`.
- Golden oracle stage `world_nbt` (`WorldNbtOracle` plus `check_world_nbt.exs`):
  - It runs the pinned dedicated server headless (seed 20261020). Console
    commands add a chest with a named item, a bell, a lectern, a furnace, an
    armor stand, a villager, an item and an XP orb. The commands are ASCII-only:
    SNBT escapes supply NUL, accented and astral characters.
  - It extracts all 752 NBT payloads: `level.dat`, 19 `data` files, 729 region,
    2 entity and 1 POI chunks, all zlib.
  - ValiMC decodes each to vanilla's value. A canonical SHA-256 is computed on
    both sides over sorted keys, UTF-8 strings, raw float bits and unwrapped
    list elements, as vanilla's `ListTag` unwraps `{"": tag}`.
  - Each carries data version 5023. Vanilla reads every ValiMC re-encoding back
    to an equal value.
  - 29 synthetic edge cases match vanilla's verdict, including depth 512 versus
    513, last-wins duplicates, truncations and bad lengths, ids and UTF.
    Divergence: vanilla accepts unpaired surrogates; ValiMC refuses them.
- Elixir or Rust (`bench/world_nbt.exs` on the 729 golden chunks, inflated p50
  2.7 KB and max 70 KB; one fresh process per phase holding only its inputs;
  three runs, OTP 29, 10 schedulers):
  - The first Elixir reader was budget-tuple bound (p50 154 µs, 4,480 chunks/s).
    Rewriting it for function-head dispatch, an integer node count, input-size
    byte checks and an ASCII fast path gave 11,560–13,616 chunks/s (p50 57–61 µs,
    p95 228–269 µs).
  - A native reader in `valimc_core::nbt` plus the NIF visitor builds the same
    terms with sub-binaries: 45,654–48,411 chunks/s (p50 15 µs, p95 60–64 µs,
    max under 200 µs). Disk reads use it. Inputs over 128 KiB run on a dirty CPU
    scheduler.
  - Writing stays in Elixir. The rewrite took it from 4,382 to 41,162–43,014
    chunks/s, faster than the zlib deflate (11,819–14,222/s) every stored chunk
    also pays. Inflate runs at 163,266–189,257/s.
- Parity: `test/nbt_native_parity_test.exs` checks generated trees,
  mutated/truncated/extended inputs under varied limits, the dirty path at 512
  containers, and repeated names, for the same results and the same errors.
  `check_world_nbt.exs` also compares both readers on every golden payload.
  `cargo test` covers the core parser.

Checks: `cargo test -p valimc_core` (14), `test/world_nbt_test.exs`,
`test/nbt_native_parity_test.exs`, the NBT, item and text suites, oracle stage
`world_nbt` (32 s), fast suite 1,043.
