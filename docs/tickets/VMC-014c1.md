# VMC-014c1 — Axis-ordered movement clipping

Status: Done — primitive and actual client contacts verified. October 14, 2026.
Depends on VMC-014b5b.

Resolve a requested displacement against a supplied bounded immutable shape list.
Use vanilla's Y-first order, larger horizontal component first, X before Z on a
tie. Each axis observes the original box translated by the accumulated result.
This pure calculation introduces no process or authority over client movement.

Acceptance:

- Match actual `Entity.collideWithShapes` and `Direction.axisStepOrder`, including
  signs, ties, empty lists/shapes, signed zero, epsilon boundaries and world offsets.
- Compare all cached grids and compound corner/floor/ceiling/slide fixtures using
  exact native result bits. Reject oversized lists, boxes and movement before work.
- Pass full tests, format, release, native suite, diff and public-tree audit.
- Actual 26.3/CUA: approach a two-block-high corner diagonally, then slide against
  one wall. Compare client contact coordinates with pure clipping; `/stats`,
  cleanup and reconnect. No claim of step-up or movement enforcement.

retain the requested signed zeros/tiny deltas; nonempty lists retain native
per-shape epsilon behavior. Queries cap at 128 shapes and ±64 per component.
