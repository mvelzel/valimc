# VMC-004b5 — Attribute modifiers and gameplay records

Status: Done
Milestone: M4
Parent: [VMC-004b](VMC-004b.md). Depends on [004b4](VMC-004b4.md).

The components that change how an item plays: `attribute_modifiers`,
`consumable` and `death_protection` (with their consume effects),
`equippable`, `tool`, `weapon`, `blocks_attacks`, `kinetic_weapon`,
`piercing_weapon`, `can_place_on` and `can_break` (block predicates).

Acceptance: every prototype value and constructed cases (each consume effect
type, each display kind of a modifier, tag and direct holder sets, block
predicates with states, NBT and component tests) round-trip both formats in
the `item_components` stage. Existing gameplay that reads these values from
item facts keeps working. Decoding stays within the stack's byte bound.

## Result (October 31, 2026)

The ten types are schemas in `ComponentSchemas`. The engine gained a
type-dispatched record (consume effects by their registry type, a modifier's
display by its enum), `{key, value}` maps (block state tests), compact lists
(one predicate is written alone), `MobEffectInstance` with its nested hidden
effects (an absent `show_icon` follows `show_particles`), and exact component
values, which go back through `ItemStack` and `ItemData` for every type.

A block predicate's NBT test and its partial component predicates are
refused (`:unsupported_predicate`): their data forms are SNBT strings and a
second dispatch over twenty predicate types, and only map-making uses them.
Blocks, state tests and exact components work.

The `item_components` stage now checks every codec, the hand-written ones
too: 3,860 values of 93 types round-trip both formats, and each value's data
tag equals Mojang's. `map_decorations` gained its NBT stream form on the way.
The constructed cases cover every consume effect type, all three modifier
displays, every equippable field, tool rules with tags and speeds, shield
reductions, spear conditions and single, multiple, state and component
block predicates.
