# VMC-023 — Biome/noise sampling and seed RNG

Status: In progress
Milestone: M2 real worlds
Depends on: [VMC-021](VMC-021.md) (golden vanilla worlds and chunk biomes),
[VMC-022](VMC-022.md).

ValiMC generates only a flat world. Vanilla worlds come from a seed through
random sources, gradient noises, a data-driven graph of density functions (the
noise router) and a climate-to-biome lookup. Everything later in generation
(terrain, carvers, surfaces, features) builds on these, so they must match
vanilla bit for bit.

26.3 reworked this machinery compared with earlier releases (float `PerlinNoise`
extending `GradientNoise`, compiled density samplers over buffers, `NoiseStack`,
"parity" noise constructors), so nothing is taken from older versions. Behaviour
comes from the pinned jar, via `javap -c` and a private decompilation with
Vineflower 1.12.0 (Maven Central, SHA-1 `85570609a0a5941a7d2918b6260b209de810f66f`,
in ignored `research/tools/`; sources in ignored `research/disassembly/vmc023/`),
and from oracles that run vanilla's own classes. The Rust is original.

Acceptance (parent):

- Every random source, noise and density function ValiMC uses returns vanilla's
  exact values (bit for bit) on oracle samples across many seeds and positions.
- Worldgen data (noise parameters, density functions, noise settings, biome
  parameter lists) comes from the pinned jar as generated facts, not hand-written
  tables.
- For a seed, the biomes ValiMC samples for every full chunk of a vanilla world
  generated with that seed equal the biomes vanilla stored (the `chunk_sections`
  world, seed 20261020).
- Sampling throughput is benchmarked.

## VMC-023a — random sources (October 20, 2026)

- `valimc_core::worldgen::random`, from `javap -c` of `XoroshiroRandomSource`,
  `Xoroshiro128PlusPlus`, `RandomSupport`, `LegacyRandomSource`,
  `BitRandomSource`, `MarsagliaPolarGaussian`, both positional factories and
  `Mth.getSeed`:
  - Xoroshiro128++ seeded through Stafford13 (`seed ^ silver ratio`,
    `+ golden ratio`), with vanilla's fallback state for all zeros.
  - Lemire's bounded `nextInt`; floats and doubles from the top 24 and 53 bits.
  - The legacy 48-bit LCG with Java's methods.
  - Positional factories: position hashes; MD5 (RFC 1321, written here) or Java
    `String.hashCode` for named seeds; `fromSeed`.
  - Forks, and the polar Gaussian.
- Stage `worldgen_random` (`RandomOracle`, `check_random.exs`): 400 traces of 40
  random operations over 7 fixed and 393 random seeds, covering every method,
  forks and positional factories. ValiMC equals vanilla on all 16,000 values,
  except that 41 of 1,182 Gaussians differ by up to 4 ulps. Vanilla computes
  them with `Math.log`, a HotSpot platform intrinsic not guaranteed to be
  correctly rounded. No world generation code draws Gaussians (checked across
  `levelgen` and `biome`).
- `cargo test`: MD5 reference digests, Java LCG values.
