# VMC-023 — Biome/noise sampling and seed RNG

Status: Foundation
Milestone: M2 real worlds
Depends on: [VMC-021](VMC-021.md) (golden vanilla worlds and chunk biomes),
[VMC-022](VMC-022.md).

ValiMC generates only a flat world. Vanilla worlds come from a seed through
random sources, gradient noises, a data-driven graph of density functions (the
noise router) and a climate-to-biome lookup. Everything later in generation
(terrain, carvers, surfaces, features) builds on these, so they must match
vanilla bit for bit.

26.3 reworked this machinery compared with earlier releases (float `PerlinNoise`
extending `GradientNoise`, compiled density samplers over buffers, `NoiseStack`,
"parity" noise constructors), so nothing is taken from older versions. Behaviour
comes from the pinned jar, via `javap -c` and a private decompilation with
Vineflower 1.12.0 (Maven Central, SHA-1 `85570609a0a5941a7d2918b6260b209de810f66f`,
in ignored `research/tools/`; sources in ignored `research/disassembly/vmc023/`),
and from oracles that run vanilla's own classes. The Rust is original.

Acceptance (parent):

- Every random source, noise and density function ValiMC uses returns vanilla's
  exact values (bit for bit) on oracle samples across many seeds and positions.
- Worldgen data (noise parameters, density functions, noise settings, biome
  parameter lists) comes from the pinned jar as generated facts, not hand-written
  tables.
- For a seed, the biomes ValiMC samples for every full chunk of a vanilla world
  generated with that seed equal the biomes vanilla stored (the `chunk_sections`
  world, seed 20261020).
- Sampling throughput is benchmarked.

## VMC-023a — random sources (October 20, 2026)

- `valimc_core::worldgen::random`, from `javap -c` of `XoroshiroRandomSource`,
  `Xoroshiro128PlusPlus`, `RandomSupport`, `LegacyRandomSource`,
  `BitRandomSource`, `MarsagliaPolarGaussian`, both positional factories and
  `Mth.getSeed`:
  - Xoroshiro128++ seeded through Stafford13 (`seed ^ silver ratio`,
    `+ golden ratio`), with vanilla's fallback state for all zeros.
  - Lemire's bounded `nextInt`; floats and doubles from the top 24 and 53 bits.
  - The legacy 48-bit LCG with Java's methods.
  - Positional factories: position hashes; MD5 (RFC 1321, written here) or Java
    `String.hashCode` for named seeds; `fromSeed`.
  - Forks, and the polar Gaussian.
- Stage `worldgen_random` (`RandomOracle`, `check_random.exs`): 400 traces of 40
  random operations over 7 fixed and 393 random seeds, covering every method,
  forks and positional factories. ValiMC equals vanilla on all 16,000 values,
  except that 41 of 1,182 Gaussians differ by up to 4 ulps. Vanilla computes
  them with `Math.log`, a HotSpot platform intrinsic not guaranteed to be
  correctly rounded. No world generation code draws Gaussians (checked across
  `levelgen` and `biome`).
- `cargo test`: MD5 reference digests, Java LCG values.

## VMC-023b — gradient noises (October 20, 2026)

- `valimc_core::worldgen::noise`, from the decompiled `GradientNoise`,
  `PerlinNoise`, `SmearedPerlinNoise`, `NoiseStack`, `NormalNoise`,
  `LegacyFbmInitializer` and `BlendedNoise`, and `Mth`:
  - Float Perlin octaves: offsets and permutation drawn from a random, input
    wrapping at 2^25, `f32` relative coordinates, gradients, smoothstep and
    trilinear interpolation in vanilla's operation order.
  - Two evaluation paths that round differently, both kept: point `get` (3D
    and 2D) and volume `add_to_volume`, which splits gradients into an XZ dot
    product and a Y component and walks a `Volume` (vanilla's `DensityVolume`:
    size, minimum and step per axis, Y fastest).
  - Smeared octaves: Y gradients use the fudged relative Y, the blend weight
    the unfudged one.
  - Normal noise: octaves from base octave, amplitude and modifiers;
    normalisation to the target deviation, including `DoubleStream.sum`'s
    compensated summation (JDK 18+) and the legacy parity factor; two
    positional factories seeding each octave from `octave_N`, the second set
    at frequency factor 1.0181268882175227.
  - The legacy nether climate initialiser (sequential draws, 262 skipped draws
    per dropped octave) and the blended noise octave sets (16, 16 and 8
    smeared octaves).
- Generated facts: `priv/worldgen/noises.json` holds all 64 `worldgen/noise`
  entries as vanilla's codec encodes them (stage `worldgen_facts`,
  `WorldgenFactsOracle`).
- Stage `worldgen_noise` (`NoiseOracle`, `check_noise.exs`): over 10 seeds,
  every registry noise built as `RandomState` builds it from Xoroshiro and
  legacy positional factories, both legacy nether climate noises, and the three
  octave stacks of the three vanilla blended noises plus one synthetic set
  (from the `minecraft:terrain` random and the legacy random): 1,540 noises.
  Points mix sampler-scaled block coordinates, random values, far values that
  wrap and edge values (±0, ±2^24 neighbours); volumes use random sizes,
  steps and scales. ValiMC's parameters come from the committed facts. All
  315,871 samples (3D points, 2D points, volumes) equal vanilla's bit for bit.
  A flipped bit in one sample fails the check.
- Noise value ranges arrived with VMC-023c, which needs them.

## VMC-023c — density functions and the noise router (October 20, 2026)

- Generated facts (stage `worldgen_facts`): `density_functions.json` (all 55
  `worldgen/density_function` entries) and `noise_settings.json` (per noise
  settings entry: noise bounds, legacy random flag, noise router and aquifer
  functions), encoded by vanilla's codecs with registry references as
  identifiers. Floats are written as their exact double value.
- `valimc_core::worldgen`, from the decompiled `densityfunction` package,
  `CubicSpline`, `Interval`, `RandomState`, `SimplexNoise` and
  `MultiNoiseBiomeSource`:
  - `density`: every function type vanilla's data uses (constants, noise with
    shifts, the three shift noises, gradients with three tilings, unary and
    binary operations, splines, lerp, clamp, range choice, interval select,
    cache, interpolation, slices, top-surface search, blended terrain noise,
    End islands, distance to a point, blending and beardifier inputs), compared
    by value like vanilla's records, with domain axes and float value ranges
    (`interval`, Java `Math.min`/`max` semantics in `java`).
  - `compiler`: vanilla's `RandomState` and `DensityFunctionCompiler`. Noises
    are seeded per identifier from the world seed (the nether climate noises
    from their own legacy randoms); references are inlined; caches with equal
    inputs share one prepared cache; functions that ignore an axis their
    parent uses are sliced at 0 on it; compilation takes vanilla's shortcuts
    (constant operands, `min`/`max` decided or bounded by ranges, constant lerp
    ends, constant range choices).
  - `sampler`: every compiled sampler with separate point and volume paths, as
    vanilla rounds them, and the sampling context's cache cells: a cached point
    inside the last cached volume's grid reads the volume's value.
- Not supported yet: `pow` and the rounding functions (no vanilla data uses
  them) and non-empty blending or structure terrain inputs (contexts without
  them use vanilla's fallbacks; terrain generation brings them).
- Stage `worldgen_density` (`DensityOracle`, `check_density.exs`): over three
  seeds and all seven noise settings, every router, aquifer and registry
  function (2,880 cases): points (some ±30,000,000 blocks away), noise-cell,
  block-step, odd-step and column volumes in uncached contexts; a cell volume
  then on-grid and off-grid points in cached contexts; and each climate
  function over a chunk's quart volume in a cached context, as chunk biome
  generation samples it. All 340,182 samples equal vanilla's bit for bit. A
  flipped bit in one sample fails the check.

## VMC-023d — climate sampling and biome lookup (October 20, 2026)

- Generated facts: `biome_parameters.json` holds both multi-noise presets
  (overworld 7,594 entries over 56 biomes, nether 5) in vanilla's order, with
  quantized parameter bounds and offsets as integers.
- `valimc_core::worldgen::climate`, from the decompiled `Climate`,
  `MultiNoiseBiomeSource`, `ChunkGenerator.doCreateBiomes` and the bytecode of
  `LevelChunkSection.fillBiomesFromNoise`:
  - Climate values quantised as vanilla does (`(long)(v * 10000f)`).
  - The parameter R-tree built exactly as vanilla builds it (bucket sizes,
    stable sorts by bucket bounds and centre magnitudes), searched as vanilla
    searches it: from the previous result, replaced only by a strictly closer
    point. Where several biomes are equally close, the answer depends on lookup
    history, which vanilla keeps per thread; callers pass it explicitly.
  - `Worldgen::fill_biomes`: a chunk's six climate functions over its quart
    volume (4 × 96 × 4, step 4) through one cached context, then one lookup per
    quart, sections from the bottom, X outer, Z inner. Fresh chunks have no
    blending (vanilla's empty blender leaves biomes unchanged).
  - `Valimc.Worldgen` parses the four fact files into the native registry once
    per VM.
- Stage `worldgen_biomes` (`BiomeOracle`, `check_biomes.exs`): the pinned
  server generates seed 20261020 around spawn (400 full chunks); the oracle
  records their stored biomes and computes vanilla's single-thread reference
  for them and for 300 chunks scattered up to 30,000,000 blocks away (48
  biomes in all), with a digest of every climate target. ValiMC's targets and
  biomes equal the reference for all 700 chunks, and all 614,400 stored quarts
  equal the world; the check would accept a stored difference only where both
  biomes are at the minimal climate distance (none occurred). Altering one
  stored or one reference biome fails the check.
- Benchmark (`bench/worldgen_biomes.exs` with `BiomeOracle bench`; raw results
  in ignored `bench/results/`): the same 256 overworld chunks on one thread,
  ten timed passes after warm-up. Median per chunk: vanilla 388.2 µs
  (OpenJDK 64-Bit Server VM 25.0.4.1), ValiMC 222.1 µs (1.75×), on the 10-core
  development Mac (OTP 29, Elixir 1.20.4). ValiMC's figure includes
  encoding the climate targets for the NIF caller.
- Not covered yet: the End's biome source, legacy-random dimensions' chunk
  biomes and blending with old chunks; worldgen is not live in play (the
  server still generates flat worlds), so VMC-023 stays Foundation until
  terrain generation (VMC-024) uses it.
