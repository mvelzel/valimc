# VMC-077z1 — One frame source, one checkpoint path

Status: Done
Milestone: foundations II (between M2 and M3)
Depends on: [VMC-077f](VMC-077f.md) (log and checkpoints),
[VMC-077s](VMC-077s.md) (frames from what changed), [VMC-077t](VMC-077t.md)
(kept frames, detached unloads, the per-owner index), [VMC-077w](VMC-077w.md)
(ticks per chunk, acknowledgements per record).

Before: the storage fixes of VMC-077s, 077t and 077w removed the stalls but
left their scaffolding (re-verified on d3fd035d):

- Two frame sources. A section kept an in-memory copy of its frames since its
  checkpoint (up to 64 MiB, then it fell back to the log), although the log's
  per-owner index already reads exactly an owner's frames.
- Three checkpoint modes. `sync: true` wrote in the group process, which then
  held the file lock, so a waiting load polled every 100 ms; `detach: true`
  waited for its task's lock with no timeout or monitor and reported to the
  log itself, skipping the checkpoint count; the commit tick's ran in a task.
- The scheduled ticks' journal was cleared by each caller
  (`ScheduledTicks.settled/1` after every commit, checkpoint and load), and
  the storage kept the unsettled struct as committed, so the identity
  shortcut never matched after a tick change.
- The tick record format lived in three modules (`ScheduledTicks.records`,
  `RegionStorage.shift_ticks`, the load's due arithmetic and
  `ScheduledTicks.dump/load`, the last used only by a test).
- Each stored part was described four times (changes, records, the motion
  flush's `part_of`/`current`, restore); item changes rebuilt every ledger
  record twice per change.
- `apply_ops/2` encoded ops to decode them again; the log acknowledged in two
  shapes; its started marker shared the index table; `RegionLog.append/2`
  served only tests.

Acceptance:

- A section's frames come only from the log: a checkpoint task syncs the
  section's route, reads its frames by the index (located by the stripe,
  read by the task with `RegionLog.read_at/1`), folds and writes them.
- Every checkpoint is written by a task holding the file's lock: the commit
  tick's reports back, a flush or shutdown waits for its result, an unload
  waits until it holds the lock (monitored). The task reports what it covers
  to the log and counts `:region_checkpoints`; a load waits on the holder's
  DOWN, without polling. A checkpoint never replaces a newer one.
- No owner settles a journal: the scheduled ticks have none. A chunk's
  container nothing changed stays the same term, so the storage diffs the
  containers by identity like every other keyed part (at most 64 a section).
  `ScheduledTicks.record/1` writes a chunk's record and `from_records/1`
  reads them back; `dump/load`, `changes`, `settled` and the restore's
  re-sorting are gone.
- One description per stored part (`fields/2`: keyed maps of entries, each
  with its record) feeds both a frame's changes and a checkpoint's full
  records; restore is its one inverse. Item changes compare the ledger's
  receipts by entry instead of rebuilding every ledger record. A deferred
  record keeps its current value, so the motion pass writes it without
  looking it up (`flush`, `part_of`, `current` are gone).
- `fold` takes decoded ops; the log acknowledges `{:storage_durable,
  [{owner, seq}]}` in every case; started stripes have their own table;
  `RegionLog.append/2` returns locations.
- Behaviour unchanged: storage, log, region, checkpoint, crash-recovery,
  player-storage and scheduled-tick tests; `mix test.fast`;
  `check_vanilla.py --changed`. Net fewer lines.

Trade-off: a log record holds every frame of one group commit (and several
commits share one up to 16 MiB), so a checkpoint reads whole records to get
its section's frames since the last one, about 1 MiB of its own. That read,
its checksums and its decode now run in the checkpoint task, off the group
and off the stripe, instead of a copy held in memory (up to 64 MiB a
section). If a flight profile shows the tasks competing with generation,
the next step is records whose owner frames are addressable on their own,
not a second copy.
