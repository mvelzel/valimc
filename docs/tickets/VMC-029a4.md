# VMC-029a4 — Deterministic block loot

Status: Deterministic loot native-verified; basic live composition automated-verified
in [VMC-029a6](VMC-029a6.md). Actual-client gate and broader loot remain pending.
October 16, 2026. Parent: [survival mining](VMC-029a.md).

Acceptance: original immutable loot facts cover structurally deterministic native
block tables, including Silk Touch and its held/stored negatives. Validate every
supported state through actual native `BlockState.getDrops`, using the original
tool before mining wear. Wrong harvest permission yields no loot. Unsupported
random/count/component/context rules remain explicit, rather than invented drops.

Use the native registry/resource loader for tables and predicates. Publish only
normalized observations and original code; raw native data stays ignored. This
slice covers loot calculation, not player permissions, experience, neighbor/block
callbacks or the complete loot system. Sample item UUIDs once when preparing the
durable source intent; the pure catalog owns no process or randomness.

Reference: pinned Mojang26.3 jar SHA1
`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`, `RegistryDataLoader`,
`BlockBehaviour.getDrops`, `LootTable` and `minecraft:tool/can_silk_touch`.
Private bootstrap/evaluation experiments: `.local/MiningLootProbe.java`,
`.local/mining-loot-{bootstrap,evaluation-02}.log`.

`MiningLootOracle` loads all native reloadable registries, classifies only known
deterministic table constructs and verifies actual drops for every supported
state. Custom `getDrops` overrides remain unsupported; the initial moving-piston
probe exposed that required block-entity context. Do not treat an absent table
as proof that an overridden method returns nothing. An initial fixture also
required the server's random-sequence callback, rather than the level's callback.

The catalog covers930 block families/30,121 states, in851 shared profiles/16,516
bytes. Seven original-tool variants pass210,847 native state/tool contexts:
ordinary/empty, direct Silk Touch1 and255 on different item types, stored-only
Silk Touch, Fortune255 and Silk+Fortune. Pure Elixir comparisons and all35,723
wrong-harvest controls pass. Fifteen affected loot/tool/wear/player-source tests
pass. Lookups reuse the existing state-to-block binary and immutable stack lists;
there is no runtime loot interpreter, owner or RNG for deterministic rules.

Logs `.local/mining-loot-{native-03,check,tests}.log`; generated raw cases remain
ignored. Random/count/component/context rules, including normal ore Fortune and
slab counts, remain explicit unsupported results. Block destruction side effects,
experience and live start/abort/stop are not established by this loot catalog.

Client scenario after live mining: dirt/planks self-drop, stone versus Silk Touch,
glass with/without Silk Touch, final-use tool retaining its original loot context,
wrong harvest tool and reconnect/retry conservation. Dedicated tester owns GUI.

The [stateful-count extension](VMC-029a7.md) now covers1,108 families/231,455 native
contexts with shared count-bearing profiles and compact state overrides. The
original30,121 states retain both observed tool branches and counts. Only the
