# VMC-003 — Persist validated player pose

Status: Awaiting failure-boundary follow-up; client scenarios passed. Updated: October 13, 2026. Depends on VMC-002.

## Scope and acceptance

Currently every join resets to spawn. Restore XYZ and yaw/pitch for the same
offline UUID before login teleport, spatial publication and chunk selection.

- A first visit uses spawn; disconnect/reconnect and graceful server restart
  restore the latest validated pose, including rotation and negative coordinates.
- Periodic checkpoints run outside the socket owner and allow only one pending
  save per connection. No per-movement disk traffic or global save coordinator.
- A unique per-UUID writer lease prevents overlapping/stale writers on reconnect.
  Admission remains reserved until final save completes or the old owner exits.
- Bounded, versioned, checksummed files validate identity and pose. Corrupt or
  unreadable saves reject only the affected login and are not overwritten.
  Write failures are reported and disconnect only the affected session.
- A killed connection can lose changes since its last checkpoint. No claim of
  crash durability, full player persistence or vanilla file compatibility.

Actual-client scenario: F3, move away from spawn and rotate view, record pose,
disconnect/rejoin localhost, verify pose; gracefully restart with client connected,
rejoin and verify again. Then `/spawn` and reconnect verify teleports save too.

## References and ownership design

Pinned vanilla jar `33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`:
`Entity.saveWithoutId/load` stores position and rotation;
`PlayerDataStorage.save/load` keys storage by UUID and replaces a temporary file;
`PlayerList.placeNewPlayer/save` restores before entering play and saves on leave.
Focused private `javap` dumps are in ignored `research/disassembly/`.

Pumpkin `b0c48b2d7688`, `pumpkin-world/src/data/player_data.rs`, uses UUID-keyed
NBT storage; SteelMC `f6fb4e49778c`,
`steel-core/src/player/player_data_storage/file_storage.rs`, serializes per-file
writes and uses atomic replacement. Paper `a2d844f71e27`, feature patch
`0014-Incremental-chunk-and-player-saving.patch`, spreads autosaves over time.
Our original Elixir design uses supervised, monitored per-session file owners
instead of mutexes or a global tick's player-save loop.

Writers register by UUID and stop after final save/owner loss. Registration holds
through I/O; a racing reconnect is rejected while the old lease is closing.
Disk reads run after writer initialization so they do not block the dynamic
supervisor. Connection shutdown flushes its latest accepted pose while writers
are still alive. Fixed-size preview files live under `world/players/*.pose`;
this is deliberately not vanilla `.dat`/NBT. Bounds follow the existing creative
preview; authoritative physics/vanilla movement limits remain VMC-014/015.

## Verification

All 27 ExUnit tests pass. Regression tests cover reconnect, supervised shutdown,
negative coordinates and
rotation, invalid/checksummed/oversized/wrong-UUID/version files, real I/O errors,
lease fencing, bounded checkpoint queues and isolation from healthy players. A
valid movement followed by a bad frame in the same batch preserves that movement.

Actual 26.3 computer-use evidence on October 13, 2026: keyboard strafing to
XYZ -5.540 / 64.000 / 0.500, disconnect/reconnect restored the same coordinates.
Moved to -8.127 / 64.000 / 0.500; a full graceful release stop/start while connected
then rejoin restored them. Original mouse gestures did not change yaw/pitch.
A controlled pose fixture written through the production writer while disconnected
set yaw 120 / pitch -25; the client displayed both and moved to -9.806 / 64.000 /
-0.469. This fixture is not evidence of mouse-driven camera input.

explicit primary/secondary clicks, Retina coordinate scaling, focus/regrab,
fullscreen and SDL system-scaled input did not change the F3 angles. The installed
SDL is 3.4.14. SDL documents a GCMouse event path that can bypass synthetic Cocoa
events; its 3.6 development API adds `SDL_MAC_USE_GCMOUSE=0` for remote-control
tools. An isolated official SDL checkout at
`ab5541ec5d4377dcc20a701897437f07ba71566f` was built under ignored `.local/` to
test this backend; the library and upstream source remain ignored. Library SHA-256:
`934465deee61c4acf354758b097d249897210b1082659790c6a17734daac246b`.

Locked-session computer use was subsequently enabled and authorized by the
user. The opt-in Cocoa event-position adapter now supports repeated rotation on

Before publication, add a focused regression for a batch that changes from
