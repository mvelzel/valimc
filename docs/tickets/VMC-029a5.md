# VMC-029a5 — Owned mining attempts

Status: Pure attempt/animation foundation native-verified; live composition pending.
October 16, 2026. Parent: [survival mining](VMC-029a.md).

Acceptance: one bounded attempt on the player owner tracks start/abort/stop,
current-rate progress and changed crack stages. Early stop waits for completion;
ordinary active ticks do not authorize destruction before the client stops.
Changed target state, invalid permissions/contact, mode/death/disconnect and stale
callbacks retire the attempt. Only a fenced, durable region commit changes blocks.
No per-block process or new global timer.

First verify actual native action/tick traces and the destruction animation codec.
Keep pure progress separate from world queries, receipts, inventory and RNG.
Compose the existing player clock and bounded query lane afterward. Record any
intentional departure from incidental upstream scheduling behavior explicitly.

Reference: pinned26.3 `ServerPlayerGameMode.handleBlockBreakAction`, `tick`,
`incrementDestroyProgress` and `ClientboundBlockDestructionPacket`; jar SHA1
`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`. Private disassembly remains ignored.

`MiningAttemptOracle` invokes the actual native start/tick/stop methods with
controlled reach, permissions, base block reads and supplied speed/harvest. Its
490 traces match instant starts, active cracks without implicit completion and
the0.7 stop threshold. Actual destruction is intercepted, excluding loot/world
effects. All165 native animation codec cases match across ID/position boundaries
and every visible/clear stage. Redundant out-of-range visual clears are coalesced.

The pinned delayed branch passes its absolute start tick into progress. Actual
stone traces started at0 remain delayed after65 ticks; the same early stop started
at123 destroys on the next tick. ValiMC deliberately uses elapsed owner ticks,
with the ordinary1.0 completion threshold, so server uptime cannot grant or deny
mining credit. Abort consumes the whole attempt identity, including finishing
state and stale callbacks. New attempts cannot inherit an old callback identity.

Four affected boundary regressions plus existing mining/player-speed tests pass.
Logs `.local/mining-attempt-{prototype,native-final,check-final,tests-final}.log`.
This module does not yet run on a connection, reserve a block, admit a client
action, or commit destruction. Next: renewable region fencing and live composition
on the existing player clock/geometry lane; no new global timer.

Renewable fencing: a live region permit can extend its existing10-second window
without changing token, expected blocks or bounded permit count. Expired,
released, mutated/ABA and restarted-owner identities cannot revive. Uncommitted
attempts can release their permit early; releasing after application cannot undo
the committed receipt or duplicate its drops. Nineteen affected permit/region/
source-recovery tests pass, including actual owner calls, stale epochs and
receipt-backed rejection after release. `.local/mining-renewal-tests.log`.
These internal APIs do not yet change live client mining behavior.

Client scenario: mine dirt/stone using correct and wrong tools; release before
completion, switch target/tool, stop early, leave reach and race another miner.
Observe cracks clearing and no unauthorized block/drop/wear changes. Then check
successful atomic destruction, final-use wear, retries and reconnect. Dedicated
tester owns the actual-client gate; pure/native checks alone cannot complete it.
