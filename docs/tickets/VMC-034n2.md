# VMC-034n2 — Durable pending cooking awards

Status: Done within unused pending-storage scope at `65061b9`.
Depends on [award values](VMC-034n1.md); part of [earned output](VMC-034n.md).

Preserve a decided XP/recipe award alongside a container transaction before any
entity or player effect. Keep output withdrawal refused until the full delivery
path is implemented; storage acceptance alone must not enable it.

Direction: reuse the region's leased writer and atomic container snapshot/joint
block-item-container journal. Region ownership covers pending awards; no process
per award and no independent file whose acknowledgement can diverge from cleared
credit. Inspect `Containers`, `ContainerTransfers`, `MiningRecord`, `Store` and
`PlayerContainerIntent/Transfers` selectively.

Implementation boundary: an internal, unused transfer planner stages pending
awards in a version-4 container snapshot. The live connection/region path continues
to use the refusal planner. Pending decisions survive container removal; creating
new destruction awards and acknowledging delivered effects remain follow-ups.

Acceptance:

- Bound award count/bytes, recipes and entropy. Bind one immutable decision to
  source UUID, transfer sequence/digest, owner region and authoritative spawn pose.
  Preserve zero-XP recipe unlocks and the exact fractional outcomes across retries.
- Atomically retain output-slot changes, cleared uses, pending XP/recipe effects
  and the terminal typed receipt. Rejection/capacity failure retains all credit.
  Removal must retain awards after the block/container entry disappears.
- Decode existing container/journal versions without inventing pending effects.
  Validate malformed/oversized/duplicate records and interrupted-write recovery.
- Retrying a typed action or replacing an owner must not append another award.
  Later materialization/recipe delivery requires durable acknowledgement before
  removing pending records; receipt compaction must preserve that guarantee.
- Targeted persistence/replay/stale-epoch/capacity tests and actual-client
  ordinary cooking/refusal/restart regression on an isolated frozen checkpoint.
  No XP entity, pickup, unlock or finished-furnace claim at this boundary.

Next: [owned orb materialization](VMC-034n3.md), native replication/pickup,
