## Acceptance and client scenario

- Discover SESSION/verify through the pinned production discovery endpoint over
  verified bounded HTTPS. Online mode uses the published route, with no fixed-route
  fallback on initial failure/offline/missing endpoint. Retain strict HTTPS, URI,
  JSON and byte limits. Preserve native existing-query concatenation.
- Match authlib's first-attempt readiness, last successful document retention,
  24-hour refresh and initial 1/2/4/8/16/32/64-minute capped backoff. Cached documents
  remain usable after transport/parse failure; a successful offline/missing-route
  document publishes unavailable. Do not cache authenticated session results.
- One supervised discovery owner publishes immutable protected ETS observations;
  one monitored linked worker performs HTTPS. Authentication workers await initial
  readiness within their own deadline through bounded subscriptions; sensitive
  owners never perform discovery I/O. Duplicate refresh triggers, late results and
  stale timers cannot create parallel jobs or overwrite a newer incarnation.
- Offline startup makes no external requests. Discovery owner/worker failure
  closes pending I/O and recovers independently without disconnecting admitted
  players. Define cold-start, failure and service-unavailable behavior explicitly.
- Meaningful schema/native route/backoff, startup readiness, retry/cache, saturation,
  cancellation/deadline, stale result and owner recovery tests; full standard checks
  and Mojang oracle. Keep manifests/captures/reference bytecode ignored.

## Native references and architecture

Mojang 26.3 authlib 10.0.77 MinecraftServicesEnvironment/DiscoveryService,
DiscoveryResponse/Discovery/Endpoints/Endpoint, RetryableFetch and its worker.
Private bytecode: `research/disassembly/VMC007-{discovery*,retry*,environment}.txt`.
Production URL is `https://discovery.minecraftservices.com/minecraft/client`.
The existing private October 14 manifest resolves SESSION/verify to the current
sessionserver endpoint; runtime must consume discovery rather than assume it.

Native supplier waits for first attempt completion, returns offline until a value
exists, replaces only on a present parsed response, resets initial failure count
on success, retains the last document on failed refresh, and refreshes every 24
hours once any document exists. Initial retries cap the exponent at six. Implement
original OTP ownership, fences and protected ETS rather than Java futures/threads.
A nested supervisor isolates discovery-owner recovery from player supervision.
No global gameplay coordinator, new Hex dependency or stored account credentials.
