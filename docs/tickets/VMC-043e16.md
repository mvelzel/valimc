# VMC-043e16 — Shulkers block player movement

Status: Awaiting client
Milestone: M3
Depends on: [VMC-043e15](VMC-043e15.md), [VMC-077l2](VMC-077l2.md).

A living shulker is a solid entity for a player, with the physical lid box
in its current attachment direction. Supply bounded immutable collider
observations to the existing player movement and rest kernels. The owner
continues to hold entity state; observations confer no mutation authority.

Acceptance:

- Player movement, pose fit and resting server travel account for live
  shulker boxes; dead shulkers and spectators do not block movement.
- Reads include a lid extending from a neighboring chunk or section, and
  fail closed if the complete candidate set exceeds the collider bound.
- Native collision probes match; live owner tests exercise the published
  collider path without a graphical client.
- Existing block-only callers remain supported. Actual-client testing is
  deferred at the user's request.

Reference: Mojang 26.3 server SHA-1
`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`, `Shulker.canBeCollidedWith`,
`Entity.collide`, `EntityGetter.getEntityCollisions`, `Player.updatePlayerPose`
and `ServerGamePacketListenerImpl.isEntityCollidingWithAnythingNew`.
Mob movement collision and displacement by an opening lid remain follow-ups.

Implementation: the optional family `collider/2` hook supplies a living
shulker's physical box. `Entity.Publication` keeps compact per-chunk collider
rows alongside observer rows, with stamps that change only when those solid
boxes change. Player physics reads complete nearby rows across section
boundaries, prefers the newer handoff generation and refuses more than 256
intersecting candidates. It reuses `Physics.EntityCollisions`' validation and
filtering; no owner calls or new authority are introduced. Two blocks of
horizontal halo include the current shulker's maximum 1.5-block reach.

The existing move/rest NIFs accept optional entity boxes, retaining their
block-only Elixir arities. The same immutable extras feed displacement,
new-collision admission and pose fit. Spectators bypass the extras. Nearby
collider stamps join the resting pose signature, so an opening lid can
invalidate a stationary player's cached fit without metadata changes.
Mount/vehicle relationships remain outside M3's implemented scope.

Validation: 840 actual native player collision and server admission
cases match across six faces, five peek amounts, living/dead shulkers,
three movement axes and both directions. The 27 player physics, pose,
publication and socket tests pass. They include real neighboring-section
owners, support on a closed shulker, a moving overhead lid, death, spectator
movement and a complete
257-collider query that refuses rather than truncating. Both changed Rust
crates pass (124 core tests); workspace Clippy and a NIF build without the
parity feature pass. All 113 affected vanilla stages pass (354 seconds,
137 cache hits, no unverified regeneration steps). Evidence:
`.local/m3-shulker-solid-{native,check,tests,rust,changed}.log`.

Deferred actual-client scenario: a closed and open shulker block walking,
a player stands on one, a lid overhead changes the available pose, and the
space becomes free after its death. Opening-lid push is a separate gate.
