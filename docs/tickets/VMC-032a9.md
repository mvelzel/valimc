# VMC-032a9 — Live ordinary chest menus

Status: Planning; VMC-032a8 presentation validation remains independent.

Acceptance: open a current single chest through the block owner, with native hand/
secondary-use, lid obstruction and valid-view rules. Use an owner-fenced immutable
snapshot for the3×9 menu. Apply supported pickup/shift/number/offhand actions via
VMC-032a6 admission and durable player→region→player exchange; refuse unsupported
predictions/gestures without changing items. Coalesce bounded viewer replication;
refresh stale views, close on removal/relocation/owner loss and preserve cursor
cleanup through disconnect/reconnect. No global hot-path coordinator or process
per chest. Source intents must finish before conflicting inventory/death cleanup.

First expose a coherent ignored chest fixture through real viewing/exchange;
fixture creation does not establish gameplay placement/removal. Those callbacks
must use the joint journal and spill stored items atomically before public block
mutation can remove a chest. Gate physical mutation until that path exists.

Research pinned ChestBlock.getMenuProvider/combine/isChestBlockedAt,
Container.stillValidBlockEntity and ServerPlayerGameMode.useItemOn, plus native
ChestMenu codecs/clicks already recorded in prior tickets. Verify opening contexts
and menu-bound source consistency before enabling a connection caller. Dedicated
client scenarios need actual deposit/withdraw/shift/split/number/offhand, stale
view/refusal/close/owner loss and fresh reconnect; automate competing actors too.
