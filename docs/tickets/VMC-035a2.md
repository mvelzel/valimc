# VMC-035a2 — Accepted item-step replication

Status: Implemented; dedicated client check pending. October16,2026. Parent: VMC-035a.

Acceptance: observers receive bounded accepted item position/velocity changes,
including initial tracking, coalesced updates, metadata replacement, removal and
fresh tracking. Refresh position before motion; never replay an old source intent
as an observer update. Verify native packets and actual controlled moving-item
presentation. Automatic geometry/physics scheduling remains the parent ticket.

Pinned26.3 `ClientboundEntityPositionSyncPacket` uses a `PositionPath`; linear type0
contains final Vec3, then yaw/pitch float32 and grounded flag. It contains no
velocity; use the separate native motion packet. Private inspection
`.local/item-position-{api,path-api,path-type}.txt`. An older pre26.3 layout would
misencode this packet. Keep original probes/public code separate from bytecode.

Implementation: atomic batches of at most32 supplied accepted steps, fenced by
owner epoch/item revision and queue expiry. The existing writer commits before
publication; whole batches refuse stale/invalid/cross-region input. Source receipts
remain intact. Step metadata changes only when its gravity flag changes; stack
replacement retains it. Observers track separate metadata/motion revisions and
coalesce to the latest position, sending position before velocity. Fresh tracking
spawns at the latest accepted pose/velocity; age-only changes emit no packets.
All four retained packet binaries count toward the region byte cap.

300 native position packets match exactly and decode through Mojang's actual
protocol. Original `EntityPositionOracle`, `check_entity_position.exs`; raw
`.local/entity-position-{native.json,native.log,elixir.json,check.log,verify.log}`.
Affected tests cover atomic32-step boundaries, stale/refused steps, current chunk,
durable publication/recovery/receipts, TCP existing/late observers and byte pacing.
47 pass (seed7203), `.local/item-steps-verified-targeted.log`; changed formatting
and Python syntax pass. No automatic physics or cross-owner movement is enabled.

Focused warmed benchmark: four owners,128 accepted steps/frame, one observer
capped at64 changes/frame,200 frames;1,024 plain or128 twelve-KiB-component items.
Three matched before/after runs reuse unchanged metadata instead of re-encoding it.
Median p95 plain636→567µs, components1190→476µs; component workload emits exactly
25,600 packets/614,400 wire bytes in every run. Plain byte counts vary slightly
with runtime IDs. This measures pure batching/replication, excluding geometry,
disk, sockets and full-server throughput. Raw `.local/item-steps-bench-{before,after}-0{1,2,3}.log`,
manifest/source hashes `.local/item-steps-bench-manifest.json`; workload `bench/item_steps.exs`.

Client scenario: observe an isolated item move through supplied accepted steps,
stop, retain metadata replacement and appear at its latest position on fresh
reconnect with one record/unchanged receipt. Native automatic launch/landing,
asynchronous geometry, efficient motion checkpointing and cross-owner handoff
remain VMC-035a; this API alone does not establish live physics parity.
