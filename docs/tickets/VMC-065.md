# VMC-065 — Published section snapshots for lock-free block reads

Status: Awaiting client
Milestone: M1 foundations
Depends on: [VMC-062](VMC-062.md).

Every movement, pose, placement, mining and item-geometry query used to send
`{:observe_blocks, ...}` calls (128 positions each) to the region owner and a
second verification call afterwards, so all collision reads of a 128×128 area
queued in one mailbox, and a busy owner stalled every player near it. Collision
jobs also started through one named `Task.Supervisor`, a global call per move.

After this slice:

- After every committed block change the owner publishes immutable per-chunk
  snapshots (`{{:chunk, chunk}, revision, sections}`, built by the Rust store as
  integers, `{palette, cells}` or `{:dense, cells}` refc binaries) to its protected
  publication table, then bumps `{:block_fence, epoch, revision}`.
- `Valimc.World.BlockSnapshot.read/3` takes the fence first and rejects newer rows,
  so an accepted read equals the owner's state at that revision; verification
  re-checks owner identity and fence. No owner message is involved.
- Collision jobs start through a `PartitionSupervisor` keyed by caller
  (`Valimc.Workers.collision/0`), sharing the same total cap.

Scope limits: reads of untouched chunks use the flat base profile; positions in
unloaded regions still go through cold admission. Region-wide revisions remain
the fence until per-section fencing (part of VMC-064).

Acceptance:

- A suspended owner no longer delays reads; stale rows and foreign epochs are
  rejected; owner replacement and fence changes fail verification.
- Existing movement, placement, mining, item and pose tests pass; tests that
  relied on a stalled owner now assert the new behavior.
- Measured: owner mailbox traffic per move drops to zero.

Checks (October 19, 2026): the full suite (1,758 tests) and all 176 vanilla oracle
stages pass, including plaintext/encrypted TCP sessions decoded by the official
codec. The M1 client baseline is pending.
